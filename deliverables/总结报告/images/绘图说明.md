# 报告插图

参考 [Diagram Design](https://github.com/cathrynlavery/diagram-design) 的 HTML + 内嵌 SVG 方法制作。采用白底、细边框、直角转弯连线和少量重点色，无阴影。

## 本项目样式

用户选择沿用报告墨绿色与白底。样式从报告提取，在本目录使用，不修改安装技能的全局样式或其他项目设置。

中文节点使用本机 Microsoft YaHei，网页标题使用 SimHei。采用宽800px的画布，节点名16px，中文说明13px起。专题图保持适度紧凑，主要功能总流程采用三个留白分区，突出阅读顺序和关键操作。PNG以3倍倍率渲染。

## 文件和范围

- `workbench-main-flow`：主要功能与使用流程，800×482px，8个节点；分为项目准备、AI生产与人工核验、执行与收尾三个区域。标题18px，节点说明15px。登录后进入项目，AI材料生产与人工核验分别突出，检查未确认时返回补齐，确认后进入执行和版本交付；共享及风险作为全周期支撑。
- `system-architecture`：三列架构图，6个组件、5条连接；入口、服务和模型横向排列，持久化数据位于服务下方。同步响应未单独重复绘制。
- `material-workflow`：横向四列依赖图，6个节点、6条连接。事实和资料汇入统一口径，分支生成通知和岗位简报，再经过人工核验归档。
- `activity-tree`：方案树，活动目标拆为四阶段行动，替换原有TikZ图。
- `pdca-cycle`：四步横向反馈流程图，底部单独保留返回下一轮计划的路径。
- `lifecycle-controls`：阶段结构图，以核心行动、代表材料、检查证据三个稳定维度对应四阶段；底部体现贯穿全周期的风险管理。
- `align-inputs`：五项约束通过共用汇入线连接输入契约，横向输出可检查材料。
- `risk-matrix`：5×5评分矩阵，仅显示确定的可能性与影响乘积及分级规则，不表示实际风险分布。
- `task-delivery-flow`：800×340px，7个节点；上层记录材料确认与版本冻结，下层表达任务状态，显示版本引用和退回修订路径。受阻、班次完成与整项验收分别表达。
- `weather-response`：800×408px，4个步骤；用示例项目的4×4评分、备用体育馆副馆、总协调及三组动作展示风险响应与复核。图中时间和阈值来自项目包，不表示实际活动发生记录。
- `validation-evidence`：800×412px，7个节点；用逻辑树把目标拆为规则、反例和证据，分别对应关联接口56项、共享集成82项和人员考勤88项。综合浏览器与基础回归在正文另列，避免混用统计口径。
- 每图的 `.html` 是源文件，`.svg` 为提取的矢量文件，`.png` 用于报告。
- `build-diagrams.py` 生成HTML并提取SVG；`render-diagrams.cjs` 使用本机浏览器导出PNG并检查节点文字是否溢出。

图中流程与组件依据提交`d39138e`的功能；账号采用服务端文件存储，不绘制未实现的数据库或自动OCR。
