> **2026-10-13 知识章节引用**：过程材料的「AI 生成 / 重新生成」及批量生成支持先选目录、再读取正文。知识库仍保存在原项目内，旧资料无需迁移。用 Markdown 标题（`#` 至 `######`）组织正文，可在知识条目内展开「文档目录」；没有标题的资料按整篇处理。已勾选且核验通过或标为教学示例的资料才参与引用。
>
> 单篇不超过 3000 字符、合计不超过 6000 字符且不超过 24 篇时，直接引用；否则先向 AI 提供任务及目录编号、文档名称和完整标题路径，由程序取回选中的章节正文，并保留其父章节说明。通用要求可勾选「固定引用」，同时仍须勾选「用于 AI 生成」。固定正文优先带入，超过总容量会停止并提示精简。普通章节每节最多 3000 字符，正文总量最多 16000 字符，截断和省略情况显示在引用记录中。目录最多 200 节，请求过长也会提示精简。
>
> 生成后，在材料卡片展开「本次生成的知识引用」，查看实际章节、来源、版本时间及正文快照。目录选择失败会保留原材料并停止，可重试，或只勾选需要的资料并设为固定引用。此功能是一次目录选择加一次正文生成，不是多轮自主检索；卡片工作流、AI 补空及按参考重排仍沿用原有引用方式，风险演练的 AI 建议也使用目录选章并保留引用快照。目录按 Markdown 标题识别，Word 导入后可补充标题标记。

> **任务、实名人员与交付版本**：在任务行打开「任务详情 / 记录」，从现有项目名册选择实名责任人，岗位文字继续独立保留；执行人员和多人轮班由现有排班按任务编号汇总。详情可查看接受人 / 时间、签到签退、确认工时及班次执行报告，并进入排班、考勤与材料。班次结束必须写执行报告，不会验收整项任务。
>
> 材料正文始终是编辑草稿，AI 生成与工作流 AI 结果明确标为 AI 草稿。核对后点击「确认并保存交付版本」，保存稳定材料编号、版本编号、确认人 / 时间及正文、已存附件、参考原包与填值的快照；材料改名、编辑、重新生成只改变草稿，历史版本保留。任务提交须选择一个或多个实际版本，并填写交付说明；组织者验收绑定该次提交的版本，后续新版本不会替换它。确认交付、提交、验收须登录已确认的项目账号；验收同时检查组织者邀请与人员管理资格。
>
> 生命周期仍为未开始、进行中、待验收、已验收，受阻独立记录；时间、工时、班次报告、AI 均不会自动验收。旧岗位和产出名称不推断人员或材料；缺关联提示待补充，旧文字验收保留原记录并标待核实，需退回补齐重新提交。原状态 / 百分比保留在 `legacyReporting`；共享导入的操作归入 `importedLifecycle`，材料版本标为导入待确认，不冒充当前项目交付。项目 JSON、任务 Markdown / CSV 保留身份编号与版本引用，版本快照可独立下载 JSON。纯离线保留计划和执行记录，实名交付与验收需 Node 服务；未存入系统的大附件和外链原件仍需另行留存。

## 快速开始

Windows 可双击仓库根目录的 `start.bat`：检查当前服务是否加载了最新后端及账号接口，自动替换旧 demo2 进程，随后打开页面；运行期间后端代码修改自动重载。`stop.bat` 停止服务及重载监视进程，保留项目、报名和考勤存档。

```powershell
# 在仓库根目录执行
node workbench/demo2/server.mjs
```

直接运行上述 Node 命令时，修改后端代码后需要手动重启。若注册提示「API 路径不存在」，通常是新版页面连接到了仍在运行的旧后端；运行 `start.bat` 后刷新页面即可。

打开 `http://127.0.0.1:4175/`（设 `DEMO2_PORT` 可换端口）。服务**默认只监听 `127.0.0.1`**，API Key 始终留在服务端进程、不会下发到浏览器；要让手机扫码填写参与者信息，见「[扫码填写怎么开（安全做法）](#扫码填写怎么开安全做法)」。

首次打开先登录 / 注册账号，登记姓名、联系方式、部门、技能和可服务时段，再进入项目选择。组织者新建或打开项目时自动建立共享名册并登记本人；志愿者首次打开项目需加入码，账号资料自动录入，负责人确认后分配任务。项目内无需再次登录或重复填写资料。本地演示身份保留在登录页的折叠入口，用于无账号的离线演示。想看完整策划示例，可从帮助页点「载入示例项目」。

## 视图一览

顶部标签栏一次切换一个视图，标签上的数字是该项目里的条目数；带 `data-goto-*` 的元素（总览的待办 / 阶段块 / 节点 / 产出，门禁的「去补」）点一下会直接跳到能处理它的视图并定位到具体那一条。

## 填写路线图（按顺序引导）

「不知道从哪开始、填到一半不知道还差什么」是这类工作台最容易让人卡住的地方，所以把主线做成了有顺序、能自动判断进度的路线图：

- **9 步固定顺序（7 步必做 + 2 步可选）**：填基本信息 → 勾选产出 → 任务分解 → 风险预案 → 人员与资源 →〔可选〕参与者信息收集 →〔可选〕素材库 → 逐份生成材料 → 确认阶段检查点
- **完成状态由项目数据推断，不用手动打勾**：判断逻辑集中在 `core/guide.js`——「填基本信息」看 3 个必填项齐不齐，「任务分解」看是不是 4 个阶段都有任务，「过程材料」看勾选的产出是不是都生成了。做完一步，下一步自己变成「当前」
- **总览顶部是完整路线图**：每一步显示标题、当前进度文案与「去做什么」，点任意一步直接跳到能处理它的视图（复用统一的 `data-goto-*` 跳转，带阶段筛选与定位高亮）
- **顶栏常驻「引导」按钮**：任何页面都看得到「引导 3/7 · 下一步：生成任务分解 →」，点一下直接过去；空项目时显示「先建项目」，走完显示「7/7 步已完成 ✓」
- 顺序不是硬性要求：路线图只标「当前建议做这一步」，不锁任何入口，想先跳着做别的也可以

材料层再顺一层：挂了参考表的卡片点 **逐格填空** 会一次只显示一格（第几格 / 共几格 + 栏目 + 字段名 + 参考原文 + 默认值来源），填完自动翻到下一个空格；**✦ 让 AI 只填这一格** 只把这一处交给模型（上下文围绕单格，比整批 12 个更准），回来的值连「依据」一起显示在格子下面。

## 卡片工作流（把工作台当一组 agent 用）

前面那套是「固定流水线」：一条主线走下来，21 类产出逐份生成。但真实使用里常常是「先把整体思路写出来，再让它变成通知稿、报名须知、主持词」——顺序和口径都由人来定。「卡片工作流」这个视图把工作台变成一组可以自己拼的 agent：

- **一张卡片 = 一个 agent**：挑一个技能包（21 类产出 + 任务分解 / 风险台账等结构技能 + 自己在「产出配置」里导入的自定义技能包，也可以选「自由写作」不套技能），勾上要引用的资料，再写上自己的要求，点「▶ 运行」就输出一段能直接用的 Markdown 正文。
- **引用资料自由组合**：项目信息表 / 活动安排 / 任务分解 / 风险台账 / 资源台账 / 素材库 / 方案比选 / 参与者信息 / 过程材料（已生成的正文）——勾哪几项就带哪几项，筹码上的数字是这份数据现在有多少条。
- **卡片之间互相引用**：勾「引用卡片」就把上游卡片的输出一起交给这张卡片；两种模式都能连——列表模式按住卡片左边的 `⠿` 把上游拖到上面，画布模式从卡片右侧的 `◦` 拖到另一张卡片上。「▶ 运行全部」按依赖顺序依次跑（上游在前、同层按画布上下排），前面的输出自然喂给后面的；上游还没运行时资料里会明说「这张卡片还没运行」，不会假装有内容。连线画出来就是引用关系的投影：点那条灰线断开引用，反向连会被拦下（不许成环）。
- **结果就在卡片里**：「改正文」切到可编辑的文本框（切回「看排版」是渲染后的样子），「复制文本」直接拿去用，「导出 .md」单张导出；工具条的「导出工作流（Markdown）」把全部卡片连同技能、引用、再要求与正文导成一份稿，「导出工作流（JSON）」导原始数据。
- **一键起步**：点「＋ 按产出配置生成卡片」，把「项目信息表 → 产出配置」里已勾选的产出一张张变成卡片（技能包已选好、资料先按全套挂上），再按需要删掉不用的、改改再要求。
- **与其它部分同源**：卡片进本机存档、进项目包，跟着项目切换；写入控件受角色门禁保护（只读访客能看能导出、不能改）；运行走的是与「过程材料」同一个接口（`/api/material`）与同一套技能包口径，所以「只使用引用资料里的事实、没有的写『待确认』」这条边界是一致的。
- **不替代主线**：产出配置仍然决定「这次要做哪些材料」，过程材料仍然是按技能包章节成稿的地方；卡片工作流是主线之外的自定义编排——比如第一张卡片把整体思路理清，再让后三张卡片引用它，分别写成给新生的通知、给老师的邀请和一段现场主持词。
- **二维画布（默认模式）**：卡片位置自由摆——按住卡片顶部拖动（自动对齐 8px）、拖空白处平移、滚轮缩放（以光标为锚点）、按住 Space 临时换抓手；「自动排布」按引用层级把上游排左、下游排右，一列排不下就接下一列，它只补没有坐标的卡片，你自己摆好的位置不会被冲掉。首次进画布会自动适配一次（下限 80%，保证卡片上的字能读），之后就由你说了算。
- **底部悬浮工具坞**（照着成熟画布工具的做法）：<code>选中 / 拖动</code> 两种指针模式（拖动模式下整块画布都是抓手，Space 也一样）、<code>− 100% ＋</code>（点百分比回到 1:1）、<code>适应屏幕</code>、<code>隐藏连线</code>（只留卡片，引用关系一条不丢）、<code>自动排布</code>、<code>撤销 / 重做</code>（⌘Z / ⌘Y，Windows 上是 Ctrl+Z / Ctrl+Y）、<code>搜索 ⌘K</code>、<code>放大画布</code>。
- **放大画布**：工具坞右端的「放大画布」把页面顶部的导航与说明收起来，让画布铺满整个窗口（1680×1080 上实测 1132×672 → 1648×962；1366×768 上 1132×360 → 1334×650），再点一次或按 Esc 退出；切到「列表」或别的视图会自动退出，不会把导航一直藏住。这个开关**记在本机存档**里（`state.ui.flowImmersive`，跟任务表视图 / 各种筛选同一层），刷新、关掉浏览器再打开都还是你上次选的样子，换项目也不变。画布默认高度也从「视口百分比」改成「视口 − 画布上方那些东西」（`clamp(320px, calc(100vh - 408px), 760px)`），所以 1366×768 的笔记本上不会再出现「工具坞被顶到屏幕外」——卡住时先按「适应屏幕」，还嫌小就点「放大画布」。
- **搜索画布（⌘K / Ctrl+K）**：按卡片名 / 技能包 / 再要求 / 正文过滤，↑↓ 选择、回车跳过去——视野挪到那张卡片上并闪一下，卡片一多就不用拿眼睛找。
- **收起卡片**：卡片标题右边的 `▴` 把正文收起来，只留标题与按钮（正文数据不动，收起状态跟着项目存），二十几张卡片时一屏能看全。
- **右下角缩略图**：画布比一屏大时才出现，显示每张卡片的位置与当前取景框；点一下或按住拖动，视野就跳过去。它只挪视角、不写数据，所以只读访客也能用。
- **导出 Word**：单张卡片「导出 Word」把技能 / 引用 / 再要求 / 正文排成一份 .docx；工具条的「导出 Word」把整条工作流按依赖顺序合成一份。走内置 `core/ooxml.js`，离线也出真文件。
- **列表模式还在**：顶部「画布 / 列表」切换，列表模式就是原来那种逐项编辑的样子——画布是加法，不是替换。

## 问答式补全（AI 访谈）

信息表里有「核心目标」「活动内容与形式」「已知约束」这类多句话字段，直接让模型一次写完容易空泛。改成**先问后写**：

- 点信息表右上角 `✦ 问答式补全`，工作台按活动类型出一份追问清单，一题一屏，可 `上一题` / `下一题` / 跳任意一题，圆点标出哪些已答
- 追问来自 `core/interview.js` 的本地题库：科技文化节问展区板块与互动环节，运动会问赛制与下雨备案，迎新系列问批次与站点，竞赛选拔问赛制与评审标准；`核心目标` 拆成「想达成什么」+「用什么指标衡量」两问
- 答完点 `生成并填入`：空字段直接写入（这就是「问够之后自动填表」）；**已经有内容的三个文本区在勾选后是整段替换**——原来的字会被清掉，换成生成的那一段
- **替换不是覆盖式瞎写**：生成时会把这三个字段的当前内容一并喂给模型（请求里长这样：`已知约束当前内容：22:00 前必须结束`），模型按原文重写后再写回，所以旧内容被清掉的同时，原文里仍然有效的约束、口径不会被丢掉
- 确认清单会同时列出「现在：…」和替换后的成稿，可用 `全部勾选` / `全部取消` 一键决定；默认只勾空字段，AI 重写过的已填字段默认也勾上（随时可取消）
- 写入的数字字段按 schema 存成数字，枚举值非法时写 `待确认`，与向导、AI 合并共用同一套归一化
- **每题先讲清缺口**：问题卡上一行「缺这一项会怎样」说明为什么要问（例：「板块不清，场地分区、摊位和用电都排不出来」）；AI 追问还会标出句式——依据 / 前提 / 反例 / 边界 / 替代 / 自评，优先用边界与替代
- **参考按「任务定制三条件」写**：定条数（内容 3–5 个环节、约束逐条列）、定顺序（内容按时间先后，目标先写目标再写衡量）、不许推论（只用你给的事实）
- **每题都给参考，不用从零想**：`常见做法` 点一下就填（三个文本区可连点几条拼成一句，再点一次取消；人数 / 预算给的是参考档位，点选后仍可改），`看 N 版示例` 展开后点 `用这一版` 整段采用
- **说不清也不会被硬填**：写「你帮我想」「待确认」「随便」这类不算回答——不会被写进表单，界面会告诉你还有几题没说清，让你改用上面的参考
- 关掉弹窗不丢答案：草稿存在 `state.ui.interview`，下次打开接着答

离线也能完整走完（问题来自本地题库，内容全部由你回答，不编造事实）。配了 `DEEPSEEK_API_KEY` 之后：

| 按钮 | 在线时多做的一件事 |
|---|---|
| `✦ 让 AI 再追问` | 按活动类型、名称与已填信息补 3–5 个更贴题的问题（skill `intake`，`mode: ask`）；每条都要「指认一个具体缺口 + 施加一条硬约束」，并标明句式（依据 / 前提 / 反例 / 边界 / 替代 / 自评）；字段必须落在白名单内，重复与非法问题直接丢弃，最多 5 条 |
| `生成并填入` | 把访谈回答**连同这三个字段的当前内容**交给 `intake`（`mode: compose`）重写成通顺成稿，**只作用于核心目标 / 活动内容与形式 / 已知约束三个文本区**，写回时整段替换（不是拼在后面）；其他字段一律保留你的原话；模型若回「待确认」这类占位词，一律不采用，改用你的原话拼出的本地成稿 |
| `✦ AI 再给两版` | 就当前这一题问 `intake`（`mode: draft`），让它拟 2–3 个**可以直接采用**的版本填进参考块等你点选；只给结构性建议，不编造人名、单位、金额 |

「只问空白、只填空白、人工确认」和门禁自动打勾、AI 合并规则是同一条底线：**信息表里的手改内容、任务、风险、材料正文，AI 一律不覆盖**。唯一的例外是上面这条：问答式补全的成稿在你勾选后整段替换那三个文本区，而且生成前已经读过原文。

## 阶段门禁：证据推断与自动打勾

26 个阶段检查点记的是「人确认过的事实」，所以**不交给 AI 猜**——`core/wbs.js` 的 `gateReview()` 只把项目里已经存在、能当证据的数据找出来；`autoTick()` 再把有证据的项**自动勾上**。判断依据全部是已有数据，不生成任何新事实。

「提交即自动检测」的链路是现成的：生成一份材料、登记一条资源、写完比选结论，下次渲染时对应检查点就会自动确认。例如生成《志愿者培训提纲》后，`活动筹备 · 志愿者与工作人员已完成培训` 会自动打勾，并附上证据原文「证据：志愿者培训提纲已生成」。

| 等级 | 含义 | 界面 |
|---|---|---|
| `ready` | 项目数据里有可核验的证据，例如「预算表已生成」「已比选 3 个方案并写明决策结论」 | **自动勾上**，显示 `自动` 徽标 + 证据原文 + `撤销` |
| `partial` | 有部分证据，还差一环 | 显示「部分证据 …」+ `去补 →` 跳到该补的地方 |
| `manual` | 数据推断不出来（现场布置、收口会、报名截止等） | 显示「需人工确认 …」+ `去补 →`，需要人点 |
| `done` | 已确认 | 打勾；自动来源的仍可 `撤销` |

**人工永远优先**：手动取消某个检查点后，该项记成 `muted`，之后再也不会被自动勾回来（界面显示「已取消 …（你手动取消过，不再自动勾选）」并提供 `恢复自动勾选`）。这与项目里「AI 只补空白、不覆盖用户手改」是同一条原则。确认来源与证据存在 `state.gateMeta`，随项目包一起导出/导入。

示例项目实测自动确认 7 项：`plan` 3（场地 / 分工 / 比选）+ `prepare` 1（排班）+ `execute` 1（应急安排）+ `close` 2（物资归还 / 风险复盘）；剩下 15 项里有 8 项会指明「去补 →」的具体去处。

只读访客不能改门禁：勾选框与撤销按钮都带 `data-write` 显式写入标记，编排层的 `isReadOnlyControl()` 会优先识别它——否则 `data-gate-phase` 里的 `phase` 会被只读正则误判成「只看不改」的控件，导致访客能勾门禁。（自动打勾是系统按数据派生的状态，不是用户编辑，因此只读访客也会看到同步后的真实状态。）

## 方案比选决策矩阵

把「拍脑袋选方案」变成可追溯的结构化决策：

- 候选方案 × 评价维度，权重 1–5，评分 1–5，每格可写打分理由
- 加权得分 = Σ(评分 × 权重) / Σ权重，自动排名
- 前两名分差 < 0.3 时提示「区分度不足」，要求补维度或重新打分
- 可一键载入预设（3 方案 × 6 维度），也可让 AI 给方案与评分
- 决策结论与补充说明随项目保存，并作为下游材料（策划书、执行手册）的输入

## 风险识别与分级应急预案

- **评分规则**：风险分值 = 可能性(1–5) × 影响(1–5)；15–25 高风险，8–14 中风险，1–7 低风险
- **类别**：安全与秩序、人员与健康、场地与设施、技术与网络、内容与流程、天气与环境、财务与物资、合规与审批、宣传与舆情、参与与体验（10 类）
- **四要素**：每条风险都必须写清触发信号、预防措施、现场响应、升级路径，并挂靠到任务与责任人
- **5×5 矩阵**：点击任意格子即筛选出该分值的风险，再点「清除」还原
- **覆盖度自检**：每阶段至少 2 项、覆盖至少 6 个类别（必须含合规类）、高风险 2–5 项、低风险至少 3 项、四要素与挂靠任务完整
- **分级应急预案**：按高 / 中 / 低三档生成处置卡与预案文档，可直接导出

单次生成的评分容易挤在中档，所以拆成两步：先由 `risk-register` 出清单，再由 `risk-calibrate` 只重算可能性与影响、不改内容。校准只作用于 AI 生成的风险，不覆盖用户手改的评分。

## 过程材料与 Word 模板

21 类产出各自绑定一个技能包。生成前可以挂模板，也可以挂一份往届样表当参考：

- **没提供模板** → 使用技能包内置的默认章节
- **提供了学校模板** → 按模板章节逐字对齐，并还原模板中的表格列
- **挂了一份参考件** → 按参考的栏目与字段对齐（见下节），优先级：手选模板 > 参考件 > 内置章节

支持上传 `.docx` / `.md` / `.txt`，服务端零依赖解析：`.docx` 本质是 ZIP，用 Node 内置 `zlib` 读取 `word/document.xml`（兼容条目名带反斜杠的 Windows 打包工具）；优先识别 Word 标题样式，识别不足 3 个标题时回退到「一、」「（一）」「1.」这类编号的启发式规则。

仓库内附一份合成示例：`samples/示例-学院活动策划书模板.docx`（15 个章节 + 1 张表格）。

生成结果是**结构化章节**而不是一整块 Markdown：每章可单独编辑（默认为「在线编辑」，正文与管道表格直接改），也可重新生成、导出单份或整包。

每一章写成**正文段落**还是**表格**，由「章节形式」约定：`materials.js` 的 `window.SKILLS.materialForms` 只列出**本身是清单 / 明细 / 登记表**的章节（基本信息、预算明细、岗位职责表、签到表、报名信息项…），其余章节一律写正文段落。这份约定随契约一起交给模型，所以《活动申报表》长成「基本信息表 + 内容概要段落 + 预算表 + 安全保障段落 + 审批记录表」，而不是整篇铺表格；《报名表》是「须知段落 + 信息项表 + 统计口径段落 + 编号流程步骤」。

章节本身也能改：材料卡片上的 **`章节 N`** 按钮打开这份材料的章节表，可以删掉这次用不上的章（小活动没有报名环节，就删掉《报名表》的「四、截止与确认流程」）、改名，或加一章。改动立刻生效——已生成的正文按新章节重排（**标题没变的保留原内容**，新章节先写「待补充」），下一次生成也按这份章节走；点「恢复默认」回到内置章节。上传模板或挂参考件后，章节由它们整份接管。

产出是**两个页签分工**的：「项目信息表 → 产出配置」只管勾选，生成与修改全在「过程材料」。正因为这样，产出配置的卡片上做了两个指路的东西——工具条下面那条虚线提醒写明「单个 AI 生成、在线编辑、导出都在过程材料」，并且给了一个直达按钮；已经生成过的产出，卡片右侧会多一个「查看」，点它直接跳到「过程材料」并展开那一份（卡片本身是勾选框，点「查看」不会顺手改变勾选）。批量生成跑完后，提示条上还会多一个「查看材料」按钮，点它就落到刚生成的材料上。`方案比选决策矩阵` 属于结构性产出，不生成正文文档，在材料视图里直接跳转到「方案比选」并导出 Markdown。

> 旧版 `.doc` 与 PDF 不支持，上传时会给出明确提示。

### 在线编辑：预览就是编辑面

不想碰 Markdown 也能改稿：材料卡片默认就是「在线编辑」——

- 段落、标题、引用点一下就能改，列表可以增删条目；表格的表头与单元格直接点开改，**改完失焦（或按 Enter）自动回写**，不打断输入焦点
- 回写只替换**这一个块占用的那几行**（`core/markdown.js` 的 `spliceBlock()`）：同一章里的空行、表格对齐占位（`---:`）、其它段落与章节一律原样保留
- 表格下方有「＋ 添加一行」（若该表有合计行，新行插在它上方）；行尾悬停出现 × 可删除该行（键盘 Tab 聚焦到该行也会显形），表格至少保留一行，要整表删除请切「Markdown 源码」
- 表格里的**派生值都由明细实时算出**：**「合计」行**该列数值 = 上方各行累加（容忍 `¥` / 千分位 / 尾随「元」），**「占比」列** = 该行金额 ÷ 合计金额（表头叫占比 / 比例 / 百分比 / 份额的列，或写成 `xx%` 的列），合计行的占比固定 100%
- 派生格**一律不可编辑**：合计行是 `md-total-cell`、数据行的占比格是 `md-calc-cell`，都没有删除按钮；改上方任意一格时它们**就地刷新**（打字过程中就跟着变，不需要失焦），导出也以重算值为准；确实要手改只能切「Markdown 源码」
- 想直接改文本、粘贴外部内容时，再切右上角「Markdown 源码」；两种模式改的是同一份正文

### 金额表的发票栏

金额 / 预算 / 费用类的表格（表头含「金额 / 单价 / 费用 / 合计」，或章节名带「预算 / 经费 / 决算」）会**自动多出一列「发票」**：

- 把发票文件直接**拖到对应那一行的发票格**即可上传（也可以点该格选文件），一行最多 6 张，缩略图 / 文件名即时出现
- 与素材库同一条 400 KB 规则：小图内联随项目保存，超限的只记文件名，导出前会提示单独归档原件
- 发票**只在导出时补列**（`core/export.js` 的 `withInvoices()`），键是「章节:表块:行」，正文 Markdown 保持干净——所以删行时发票跟着行走，重新生成材料会因行序变化而丢失发票，界面会明确提示
- 该行没有附件就不补空列，成品里不会出现空白的「发票」栏；「合计」行也不出发票格，避免把发票挂到汇总行上

### 上传参考：按往届样表对齐

有现成的往届申报表、学院样表时，不必再手抄栏目：**把文件直接拖到那张卡片上**，或者点卡片上的 **⇪ 上传参考**，两者等价，支持 `.docx` / `.md` / `.txt`，生成时按参考对齐。

- **纯前端解析**：`.docx` 由 `core/docx.js` 自己解 ZIP 目录，deflate 条目走浏览器内置 `DecompressionStream('deflate-raw')`。不新增服务端接口、不联网、不需要 Key，离线同样可用（旧版 `.doc` 会让你先另存为 `.docx`）
- **读三样东西**：**栏目**（含 Word 表格里的整行小标题，如「一、活动基本信息」「六、经费预算」）、**字段清单**（活动名称 / 活动时间 / 负责人姓名 / 联系方式 …）、**原文**（Markdown 化，上限 10000 字）
- **生成即对齐**：这三样随输入里的 `参考样例` 一起交给 AI；有参考时它直接作为该产出的章节（换成参考的栏目，而不是内置 5 章），字段一个不漏，且**参考里属于别的事实的值不会被照抄**——规则写在 `SKILL.md` 的「参考样例」一节，技能包改动即时生效
- **覆盖核对**：生成后卡片显示 `栏目 x/y · 字段 a/b`，参考面板里列出「参考里有、正文里还没找到」的缺项；核对只说明有没有写到，不判断内容对错
- **Word 版式也跟着参考走**：上传的 `.docx` 参考会额外抽出一套**版式套件**（样式表、编号定义、页眉页脚与其图片、页面设置、段落与表格样本），导出 Word 时照它排版——字体、字号、页边距、页眉页脚、表格线跟学校那份表一致，只有正文换成生成的内容；参考条上显示「版式 ✓」。纯前端的 ZIP + `DecompressionStream`，不外传、不需要 Key，体积超预算时按「图片 → theme → 字体表 → settings → numbering」的顺序降级，并在参考面板里说明
- **按参考重排（AI）**：正文写完后点卡片上的「⇄ 按参考重排」，AI 按参考的栏目顺序、字段清单与表格列把当前正文改写成一份成稿（缺的写「待确认」、不照抄参考里属于别的事实）；正文会被替换，旁边就是「↺ 撤回重排」。契约写在 `core/ai.js` 的 `reframeContract()`，只有连上 AI 时可用
- **参考表填值（离线保真）**：卡片上的 **⇩ 参考表填值** 把这份参考当成一张**要填的表**——表格怎么画、栏目叫什么、分几个部分、条目数量、缩进、页眉页脚全部照抄，只把识别成「值」的文字换掉：段首的「活动名称：xxx」、表格里的「字段 | 值」、`（一）` 小标题下面的正文段、以及经费表数据行里的格子（按表头列名标注）。默认值照字段名从项目信息表推出来（日期会写成「2026年11月8日 09:30—17:00」这种表里惯用的写法，填报时间用今天），剩下的可以手填，也可以点 **AI 补全空位**（带全套项目上下文：项目信息表 / 任务分解 / 风险台账 / 资源台账 / 素材库 / 参考原文，表格里的数字格也一起发；一次 12 个空位，每个 id 都要求回一行，**找不到依据的显式留空、不许编**，补完会报「已填 / 无依据 / 没回」三个数）。**留空的位置原样保留参考里的字**，勾「置空」则这一格输出为空。导出时只重写 `word/document.xml`，图片 / 样式 / 页眉页脚等部件**逐字节照搬**，所以产物就是「这份参考表本身」
- **两条路的分工**：要**保真**（形式与参考一模一样、离线可用、自己确认每一格的值）用「参考表填值」；要**成稿**（让 AI 按参考重排成一篇可读的正文）用「⇄ 按参考重排」。参考条上会显示「版式 ✓ / 可填值 / 已重排」三个徽标，各是各的
- **挂了参考件之后，Word 默认导「参考原表」**：卡片的下载区变成「Word（参考原表）」+「Word（正文）」两颗——前者就是上面那条保真路径（等同「⇩ 参考表填值 → 下载填好的 Word」），后者才是 AI 写出来的正文（版式仍沿用参考）。页头的「导出材料包（Word）」收的是 AI 正文，若库里挂着参考件，导完会提示改用「Word（参考原表）」
- **表格容错**：正文里的管道表格，表头行写短了、或整行表头是空的，都会按最宽的一行补齐列数（以前会按表头裁列，数据直接丢；预览与 Word 都会变成一排空格子）；漏写表头（分隔行写在最前面）的表也能认出来，不再退化成一堆 | --- | 竖线文本。整行表头是空的（含完全没写表头）就当无表头处理——预览、Word、Excel 里那一行都不画，数据仍是数据
- 解析出的栏目 / 字段 / 原文都能在编辑器顶部的参考面板里展开核对，可随时「换一份参考」或「移除参考」（参考件随项目存档，按产出 key 存放）

### 交付格式：Word / Excel 是真文件

每份材料的正文按 Markdown 保存，导出时由 `core/markdown.js` 解析成结构块，再由 `core/ooxml.js` 手写 ZIP（STORE 不压缩）+ OOXML 生成：

- **表格型产出**（预算表、签到表、物料清单…）主交付 **Excel `.xlsx`**：一章一张工作表，首行表头、冻结首行、加边框
- **正文型产出**（策划书、应急预案、复盘报告…）主交付 **Word `.docx`**：章节标题走标题样式，Markdown 表格转成 Word 表格；挂了参考件时整份文档按参考的版式排（参考的 `styles.xml`、页面设置、页眉页脚会打进包里）
- **图形型产出**（海报 / 宣传图）主交付 **Markdown**：`一、海报文案` 与 `二、视觉设计说明` 会被装配进生图提示词，成品由图像模型产出
- 三种格式随时都能导：卡片右侧 `Word` / `Excel` / `Markdown` 三颗按钮，`deliverable` 只决定主按钮；页头另有「导出材料包（Word）」

生成的包不是改扩展名的文本：`[Content_Types].xml`、`word/document.xml`、`xl/workbook.xml` 等部件齐全，Word / WPS / Excel / Numbers 都能直接打开。技能包通过 `registry.json` 的 `deliverable` 字段声明主交付格式，自测会校验它与 `SKILL.md` 里声明的格式一致。

## 海报 / 宣传图：装配提示词 → AI 生图

这张产出**没有在线排版器**：卡片主体就是生图区，提示词由四段自动装配，改「追加要求」即时更新，生成前能看到完整提示词。

- 四段来源：**项目信息表**（`state.project.basic`，只发填过的字段）＋ 材料「一、海报文案」＋ 材料「二、视觉设计说明」＋ 卡片上的**追加要求**框
- **完整提示词可直接改**：框里默认是四段装配的结果；一旦改过就以手改的为准（不再被四段刷新覆盖，标题会标「已手改」），点「重新装配」丢掉手改回到自动装配。生成时发的就是框里那一段
- 章节按**标题前缀**取：标题被改名或材料还没生成时，退回该材料全文；两节都没匹配上才退全文（不会把同一段正文塞两遍）
- 增补要求只进提示词，**不写回材料正文**，也不会出现在导出的 Markdown 里
- 生成结果由服务端落盘到 `workbench/demo2/generated/`，自动登记进素材库，可打开 / 删除；只读访客不能生图、不能删图

## 知识库与素材库

「知识与素材」入口可切换两类资料库。知识分为组织流程、规范与模板、风险与应急、往届经验；支持导入 Markdown / TXT / DOCX，编辑正文、登记来源和适用范围，核验后选择 AI 引用。素材支持图片、文案、链接与附件；小图片 / 附件（400 KB 内）可随项目保存，超限文件需单独归档。两个库均可检索、按阶段筛选和导出，随项目包保留与多人共享同步。

材料生成与卡片工作流使用选中的正文和来源信息；不自动读取图片、网页或 PDF。资料引用预览会说明容量限制与截断。「载入教学资料示例」提供四条知识、两张 SVG 示意图和一份文案，均明确标注示例性质。完整步骤见 [知识库与素材库搭建指南](docs/知识库与素材库搭建指南.md)。

## 参与者信息收集（可选 · 扫码填写）

校内小活动常常「到场才登记」，问什么、临时加一项，都是现场说了算。所以这里是一个**可开关、字段可自定义、离线也跑得动**的收集模块（默认关闭，关着不产生任何数据）：

- **字段自己定**：4 套预设（最小信息 / 报名信息 / 现场签到 / 活动反馈）一键铺开，之后可增删字段、改类型（文本 / 数字 / 手机 / 邮箱 / 下拉 / 日期 / 多行文本 / 勾选）、标必填、给下拉项，并指定一个「去重字段」（默认学号）用来认出重复报名
- **二维码是自己生成的**：`core/qr.js` 手写编码器（字节模式 + 纠错等级 M、版本 1–7，上限 122 字节），不引第三方库；链接太长时按阶梯降级——先省掉标题与须知、再退成只带表单序号的短链，界面会写明当前用的哪一档，装不下就明说「改用表单码」而不是偷偷截断。**「访问地址」留空就跟着当前网址走**（本机打开、静态托管、换成子目录、换端口都不用改），并且站点根 / 目录 / 整页地址三种写法都认，不会拼成 `signup.html/signup.html`
- **填写页是独立的**：`signup.html` 只靠链接里的表单定义（或手工粘贴的「表单码」）渲染，不需要登录、不需要联网；必填 / 手机号 / 邮箱 / 数字在提交前就拦下并标红
- **三条把数据带回来的路**：同一台机器上，填写页与工作台同源，靠 `storage` 事件 + 兜底轮询**实时同步**（链接里放不下项目号时，按本机已存的那份表单归属项目，所以「内置预览 / 另一个标签页」照样实时进表）；换了设备，填写页给出的**回执码**（`R1|…` 一行文本）或导出的 **CSV** 都能在「参与者」里粘回 / 导入，重复导入同一条不会翻倍；本机服务开着时（局域网或下面第 4 步的隧道）还有第三条：手机提交直接落到本机 `generated/join/`，工作台每 2.5 秒按游标拉一次，2–3 秒就进表，不用再发回执码（直传靠链接里的短码认项目：链接没带项目号、或短码过期时不会硬塞，填写页会退回「回执码」，详见 `docs/手机直传怎么开.md`）
- **收到的数据**：实时汇总（份数、签到人数、必填完整度、重复报名、最近一条）＋ 明细表（可就地改、勾选签到、删行、现场补登），可导出 CSV / Markdown
- 与技能包衔接：`signup-form`（报名表）与 `attendance`（签到表）在生成时会带上已收到的参与者记录，素材上下文同理

### 扫码填写怎么开（安全做法）

服务**默认只监听 `127.0.0.1`**，别的设备根本连不上——这是默认的安全状态。真要手机扫码填写时，手机就在旁边（同一个 Wi-Fi / 热点）走下面三步；手机不在同一网络走第 4 步。全程只把**一张填写页**放出去：

1. **先换网络**：最省事也最安全的是开**手机热点**，让电脑连这个热点（或电脑开热点让手机连）：这样「局域网」里只有你和手机两台设备。校园网 / 咖啡厅 Wi-Fi 是共享网络，同网段的其他设备也能访问，能不用就不用。
2. **换地址启动服务**（默认行为不变，只是多 listen 一个地址）：

   ```powershell
   $env:DEMO2_HOST='0.0.0.0'; node workbench/demo2/server.mjs
   ```

   启动日志会把本机可用的填写页地址逐条打印出来（带网卡名，认准 **WLAN / 以太网** 那条；`VMware` / `Hyper-V` 的虚拟网卡手机连不到）。把「参与者」里的「访问地址」改成那一条，再点「重新生成二维码」（忘了改哪条也没关系：「参与者 → ② 填写页与二维码」顶上的检测会自己指出问题——地址仍是 `127.0.0.1`、或服务只听了本机，都会写明原因，并给一颗「改用这个地址」的按钮）。
3. **首次放行防火墙**（管理员 PowerShell，只需一次，用完可以删）：

   ```powershell
   # 放行：只对「专用 / 公用网络」+「本地子网」开放，不是对全网开放
   New-NetFirewallRule -DisplayName "Demo2 参与者填写页 (4175)" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 4175 -Profile Private,Public -RemoteAddress LocalSubnet
   # 用完撤销
   Remove-NetFirewallRule -DisplayName "Demo2 参与者填写页 (4175)"
   ```

   > 这里特意带上 `Public`：手机热点、新接进来的 Wi-Fi 常被 Windows 判成「公用网络」，只写 `Private` 会在这些网络下失效。先用 `Get-NetFirewallProfile | Select-Object Name,Enabled` 看一眼——本机三档全关时其实不用放行。

4. **（可选）手机不在同一网络时，开 cloudflared 隧道**：另开一个窗口跑 `cloudflared tunnel --url http://127.0.0.1:4175`，把它打印出来的 `https://xxx.trycloudflare.com` 填进「访问地址」，再点「重新生成二维码」。隧道请求同样被当成非本机：匿名可填写，持有效邀请的成员可协作；完整步骤、安全边界与常见问题见 [`docs/手机直传怎么开.md`](docs/手机直传怎么开.md)。

**开放期间，别的设备能做什么**：匿名访客可打开填写页、取表单、提交报名与考勤，以及加载不含项目数据的工作台界面。持有效邀请的协作者可读取所属项目；可编辑成员可保存项目和调用 AI，只读访客不能写入。服务端源码与 `generated/shared/`、`generated/join/` 存档不能直接读取。手机提交落到 `generated/join/`，组织者在参与者页每 2.5 秒拉取；演示结束可停止服务，数据保留。

**不要做的事**：不要给 4175 做路由器端口映射，也不要用 ngrok / frp 这类「把整站或整台机器映射出去」的工具——那会把工作台和 AI 接口一起暴露。要跨网络就用第 4 步的 cloudflared 隧道：它是出站连接，而且服务端只对隧道请求放行填写页那几条路。也不必去追「公网 IP」——NAT 后面直接入站本来就不通。

> 只想看效果不想折腾网络：点「内置预览」，或把填写页在另一个标签页打开，提交同样会实时进表。

### 想发布到公网（静态托管）

手机不在同一网络、要让参与者随时扫（不想开着电脑热点）→ 用上面第 4 步的隧道；只想让别人看内容、不想开着服务 → 静态托管。

一条命令就能打出一份可直接上传的产物：

```powershell
node workbench/demo2/tools/pack-static.mjs
```

产物在 `workbench/demo2/dist/`：脚本按白名单挑文件（自动挡住 `.env` / `server.mjs` / `tools/` / `docs/`），拷完还会回头核对页面引用一个不少，所以它同时是「发布前检查」。上传到 Cloudflare Pages 或 GitHub Pages 的逐步做法、上线后哪些按钮会置灰、常见坑与数据迁移，见 [`docs/静态托管怎么部署.md`](docs/静态托管怎么部署.md)。

静态托管没有后端：AI / 生图 / 模板解析会置灰，其余功能照常；数据仍存在各自浏览器里，要给别人看内容就用「导出项目包」。静态托管下没有「手机直传」这条直连本机的路（页面会退回「回执码 / CSV」），要继续扫码直传就照 `docs/手机直传怎么开.md` 开着本机服务 + 隧道。

## 账号与权限（本地演示）

这不是真实鉴权，也没有账号体系：身份只是保存在浏览器里的一个角色开关，用来演示「谁能改、谁只能看」。

| 角色 | 权限 |
|---|---|
| 活动组织者 | 管理项目库（新建 / 重命名 / 复制 / 归档 / 删除）与全部内容 |
| 活动成员 | 编辑内容、运行演练、导入导出；不能删除或归档项目 |
| 只读访客 | 只能查看、筛选、切换与导出，所有写入控件被禁用并给出原因 |

- 身份切换在右上角「姓名 · 角色」处，随时可改，不影响已有数据
- 门禁是「按控件类型 + 按角色」两层判定：筛选、分段切换、导出、打开、下载等只读动作始终放行
- 视图内部重新渲染时由 `MutationObserver` 兜底，避免绕过门禁
- 权限判定只在前端生效，仅用于演示；本地服务不校验身份

## 多项目

- 每个项目独立存储：项目信息、任务、风险、比选、门禁、材料、素材、资源、演练与变更记录彼此不干扰
- 存储布局：`demo2-workbench-v3` 保存项目库索引（项目列表、当前项目、身份、界面偏好），`demo2-project-v3-<id>` 保存单个项目的完整文档（含素材 Data URL）
- 顶栏下拉可快速切换项目；「项目库」提供新建、重命名、复制、归档（可取消）、删除与项目包导入导出
- 复制项目会连同任务、风险、材料、资源与演练一起复制，名称自动追加「（副本）」
- 删除不可撤销，会连同该项目的全部数据一起清理，操作前建议先导出项目包
- 旧的单项目数据（`demo2-workbench-v2` / `v1`）首次打开会自动迁移成「项目库里的一个项目」

## 人员与资源

服务人员和物资分别管理，任务负责组织人员安排：

- **服务人员**：登录并打开项目后自动登记实名资料；负责人确认入组、授权现场管理者，查看本人任务、全部班次、签到签退与工时。人员区不提供发票入口；旧项目的人员数量保留为历史需求汇总。
- **从任务安排人员**：进入「全周期任务」，点击任务行的「安排人员」，勾选一名或多名已确认人员并填写岗位、时间、地点与执行要求；支持全选与清空。一次提交为每人创建独立班次，同一任务可安排多人、多班次；任务行展示人员与班次数，成员账号同步显示自己的任务。物资填写每人数量，页面显示总预留；任一人员冲突、技能不符或资源不足时整组不保存，表单选择保留。
- **课堂示例人员**：任务安排区和服务人员名册可「载入 10 名示例人员」，覆盖协调、签到、宣传、摄影、后勤、接待、主持、设备、财务、应急岗位。重复载入不会重复登记；可移除未排班示例，已有班次、取消历史及报告保留。示例无登录账号，不可担任实名责任人或获得管理权限；管理者可模拟接受、签到签退和班次报告，流水明确标注示例，任务仍须真实交付和验收。
- **安排之后继续执行与验收**：选定任务后，人员安排区直接显示当前状态、下一步说明和「开始执行 / 提交验收 / 验收通过 / 退回执行」等适用操作。人员列的「查看任务 / 提交与验收」可打开详情，操作也放在详情顶部；无需横向滚动寻找表格右侧按钮。提交前指定真实责任人，在过程材料确认实际交付版本，再选择版本提交，由组织者核验。班次报告与签到签退单独记录，不代替整项任务验收。
- **物资与资源**：独立维护物料、设备、场地、经费与车辆，记录库存、计划需求、借出、单价、存放地点、来源和状态。采购发票仅关联这些资源，支持上传、下载与随项目备份。
- **占用冲突检查**：计划需求超过「库存 − 已借出」时标红并给出缺口；排班另按时间段校验资源峰值与人员冲突。
- AI 和示例台账只补充物资与资源，不生成服务人员账号；载入示例保留已有条目及凭证。物料清单仍从统一台账生成，可导出 Excel / Markdown。

## 风险演练与复盘

## AI 生图

- 入口在「过程材料 → 海报 / 宣传图」的**卡片主体**（不再是设计器下方的附属区）
- 提示词不用手写：项目信息表 ＋ 材料「一、海报文案」＋「二、视觉设计说明」＋ 追加要求框，四段自动拼好，生成前可核验
- 服务端代理 YosHub `POST {YOSHUB_API_BASE}/v1/images/generations`，把返回的 `b64_json` 或图片 URL 落盘到 `workbench/demo2/generated/`，前端只拿本地 URL
- 生成结果自动登记进素材库，并保留在本项目的 `poster.images` 里，可单独删除
- 未配置 `YOSHUB_API_KEY` 时按钮置灰并说明原因；项目信息、材料正文与全部导出功能不受影响
- 提示词尾句沿用「不要生成未提供的时间、地点、主办方、品牌、二维码、数字或可读文字」；画面里的文字请用图片工具或线下排版补，或写进「追加要求」里放宽

## 数据、备份与迁移

- 数据保存在浏览器 `localStorage`：`demo2-workbench-v3` 是项目库索引，`demo2-project-v3-<id>` 是单个项目的完整文档（含素材 Data URL），不跨设备同步
- 每条数据带来源标记：`用户填写` / `AI 建议` / `待确认`，一眼区分事实与推测
- 合并规则：AI 只填空白与「待确认」，**永不覆盖用户手改**的内容
- 「导出项目包（JSON）」是唯一可跨设备迁移的格式，包含项目信息、任务、风险、比选、门禁、材料、模板、素材、海报、资源台账、演练记录、参与者收集与变更记录；「导入项目包」默认导入为一份新项目，原项目不受影响
- 早期版本（`demo2-workbench-v2` / `v1`）的本地数据会自动迁移成项目库里的一个项目
- 容量接近浏览器上限时保存会提示失败，建议及时导出备份

```
├─ generated/          运行期生成：AI 生图 + 手机直传落盘（`generated/join/`，首次使用时自动创建；`generated/` 已被 `.gitignore` 忽略）
├─ samples/            示例项目 JSON + 示例 Word 模板
├─ tools/
│  ├─ selftest.mjs     离线自测脚本
│  └─ pack-static.mjs  静态托管打包：白名单清单 → dist/，顺手挡住 .env / server.mjs / tools / docs
└─ docs/               开发计划与验收、迭代进度记录、静态托管怎么部署、手机直传怎么开、结构化提示词包-全流程环节对照
```

## 接口

| 接口 | 作用 |
|---|---|
| `GET /api/health` | 是否已配置 DeepSeek Key，前端据此决定在线 / 离线模式 |
| `GET /api/skills` | 返回技能注册表，并逐个探测 `SKILL.md` 是否存在 |
| `POST /api/structure` | 结构化表生成，入参 `{ skill, contract, input, rules? }`；`rules` 只有自定义技能包会带（服务端不进 registry，用完即弃） |
| `POST /api/material` | 材料生成，参数同上（同一处理器） |
| `POST /api/template?name=xxx.docx` | 上传模板原始字节，返回解析出的章节与表格 |
| `POST /api/image` | YosHub 生图，入参 `{ prompt, size? }`；结果落盘到 `generated/`，返回 `{ url, model, width, height }` |
| `GET /generated/<file>` | 读取生成图片（仅限 `demo2/generated/` 目录内） |
| `POST /api/signup/link` | 本机专用：登记 / 复用项目的 4 位短码（表单定义交给服务端，二维码只带短码） |
| `GET /api/signup/form?p=<短码>` | 隧道 / 局域网访客可用：手机按短码取回表单定义 |
| `POST /api/signup/submit` | 隧道 / 局域网访客可用：手机提交回执码（限流 40 条/分、单条 ≤ 8 KB、单项目 ≤ 800 条，按内容幂等） |
| `GET /api/signup/queue?project=&since=` | 本机专用：工作台按游标拉新的手机提交 |

服务端不含业务逻辑：按注册表加载 `skills/<id>/SKILL.md`（剔除 frontmatter）→ 拼上调用方注入的 JSON 契约与输入 → 以 JSON 模式调用 DeepSeek → 返回解析后的对象。自定义技能包不在注册表里：调用方在 `rules` 里把技能包正文一起带过来，服务端直接用这一份当规则——不写盘、不进 `registry.json`、用完即弃。

- 非本机请求（局域网 / 隧道）按邀请权限读取共享项目和调用管理接口；匿名允许填写页、表单读取和提交，以及公开工作台界面。服务端源码和数据存档不对外开放。
- 未注册的 skill：带了 `rules`（自定义技能包）→ 正常生成；没带 → `400`
- 已登记但未接入 → `501`，并提示应该创建哪个文件
- 未配置 Key → `503`（`/api/structure` 看 `DEEPSEEK_API_KEY`，`/api/image` 看 `YOSHUB_API_KEY`）
- `GET /api/health` 会同时返回 `providers.deepseek` 与 `providers.yoshub`，前端据此分别置灰两类按钮

## 技能体系

工作台里每一个产出都绑定一个技能包（skill）。技能包不是写死在代码里的提示词：

```
skills/<id>/
├─ SKILL.md        必需。何时使用 + 输出契约 + 事实边界 + 交付格式 + 验收清单
├─ references/     可选。按需加载的细节规范
├─ assets/         可选。模板与示例
└─ scripts/        可选。自检脚本
```

- `SKILL.md` 只做**路由**，细节放 `references/`，避免新增产出时撑大上下文
- `registry.json` 是唯一登记处；`status: planned` 的技能在工作台里显示为「待接入」
- `SKILL.md` 里的 `## 参考样例` 声明本产出怎么对待用户上传的样表（结构对齐 / 字段不漏 / 值不照抄 / 只增不改），`_template/SKILL.md` 是通用版；改它不需要重启服务，下一次生成就读到新规则
- 新增技能：复制 `_template/SKILL.md` → 写内容 → 把注册表状态改为 `ready` → 工作台自动点亮

### 两层：固定 + 可组装

「产出配置」不是写死的清单，而是由 `core/skills.js`（技能目录）装配出来的：

| 层 | 有哪些 | 怎么改 |
|---|---|---|
| **内置技能包（固定）** | 与 `skills/registry.json` 一一对应的 21 项产出；带专属视图、与工作台状态耦合的（方案比选决策矩阵）也在这一层 | 按上面的流程加 `skills/<id>/SKILL.md` + 登记表 |
| **自定义技能包（可组装）** | 用户在工作台里粘贴导入的产出，存在浏览器本地，可加可删 | 「产出配置」工具条上的 **＋ 自定义产出** |

装配方式是**原地改写**产出清单（`util.OUTPUT_ITEMS` 始终是同一个数组对象），所以每个视图在加载期解构过的那份引用都会自动看到新产出；自定义产出的默认章节同时注入 `SKILLS.materials`，过程材料、导出、模板注入全部照常走。

### 自定义技能包：约定格式

格式就是 `SKILL.md` 那一套 frontmatter，装进一段文本里：

````
---
name: safety-brief          # 技能 id：字母开头，只含字母数字与 - _（必填）
title: 参与者安全须知        # 产出名称，显示在产出配置里（必填）
kind: document             # document 文档 / table 表格 / graphic 图形（必填）
phase: prepare             # plan / prepare / execute / close（选填，默认 plan）
output: safetyBrief        # 产出的 key，不写就取 name（选填）
description: 面向参与者的安全须知（选填）
sections:                  # 章节，一行一条（必填；document/table ≥ 2 条，graphic ≥ 1 条）
  - 一、活动风险提示
  - 二、着装与物品要求
  - 三、紧急联络与处置流程
---

正文写给 AI 的写作要求（语气、篇幅、必须写到的要点、事实边界）。留空也行，
工作台会按上面的章节给一段通用口径。
````

- 行内 `#` 注释会被剥掉（`kind: document   # 文档`）；`sections` 也接受 `|` 分隔或 `[a, b]` 流式写法
- 识别不通过时弹窗里逐条说原因：缺 `title`、`kind` 不合法、章节太少、产出 key 与内置重名……
- `kind: structure` 需要工作台里配套的专属视图，暂不开放自定义；`deliverable` 必须与 `kind` 自洽（文档 → `word`、表格 → `excel`、图形 → `svg` / `markdown`），不写就按 kind 推断
- 点「识别并加入」后立刻出现在产出配置里（默认勾上）：过程材料能按它的章节生成，Word / Excel / Markdown 都能导；AI 生成时技能包正文随调用一起发给服务端（见「接口」）
- 技能库存在浏览器本地（键 `demo2-custom-skills-v1`），**换项目、重启服务都还在**；弹窗里的「导出技能包」把整库导成一个 `.md`，发给别人粘贴导入即可
- 删除：产出配置里**自定义卡片**右侧的 `×` 是「连这个产出一起撤掉」（同时取消勾选，已生成的材料保留）；技能库里每条的「移除」与列表右上角「清空技能库」是纯技能库操作——项目勾选保留，缺技能时按上一条提示
- 编辑：产出配置每张卡片右侧有「编辑」——内置产出只能改 **显示名**（按项目存，清空即恢复默认名；阶段 / 类型 / 章节 / 生成要求锁住）；自定义产出可改标题 / 阶段 / 类型 / 章节 / 生成要求，改的是技能包原文（`name` 与产出 key 不动），弹窗里的「导出技能包」拿到的就是改后的同一份
- 换了电脑、或删过技能包时，项目里勾过的产出会显示「这个项目引用了 N 个本机没有的技能（…）」——导入对应技能包即可恢复

## 已知边界

- Node 模式支持共享项目和独立人员账号；编辑草稿保存在浏览器，服务账号、名册、班次与考勤保存在服务端。本地演示角色开关用于离线演示，不能提升服务账号权限。
- 演练场景库是离线训练脚本，结论仍需人工复核
- AI 生图依赖 YosHub 接口，图片质量与中文文字可用性由上游模型决定
- 项目库的进度快照（任务 / 风险 / 材料数）只反映该项目最近一次保存时的状态
- 素材库中的图片与金额表发票同一条 400 KB 规则：超限只记文件名，需要单独传原图 / 原件
- 参考件只取前 10000 字正文：扫描件 / 图片里的字段不会 OCR，只按能读到的结构与字段对齐
- 版式套件跟着参考件存进本地存档（几十 KB 量级）：参考的样式表过大、或页眉页脚图片超出 400 KB 预算时会自动降级，导出退回默认版式并在参考面板里说明
- 「按参考重排」与「AI 补全空位」需要 AI Key；离线时这两个按钮置灰，**参考表填值是纯本地替换**（换值 + 重打包），离线完全可用
- 参考表填值：参考件整包会存进本地存档（丢掉 `word/fonts/*.odttf` 嵌入字体后通常几十到一两百 KB），所以导出用的是**这份表的原件**而不是重新排一份；被丢掉的嵌入字体会退回系统同名字体，Word / WPS 会正常显示，只有在原机器缺字体时字形略有差异
- 参考表填值只认「能读到的结构」：识别成文字的才换，识别不了的新栏目不会被造出来；扫描件里的手写 / 图片内容原样保留
- 「Word（参考原表）」导出的文档与参考的差别只有「值」：正文之外（图片 / 样式 / 页眉页脚 / 编号）逐字节照搬；扫描件、图片里的内容不会被识别成空位，原样保留
- 结构升级靠迁移逻辑；账号与考勤使用 Node 文件存储，适合课堂单进程演示，未验证公网部署。
- AI 结果依赖模型输出，生成后务必人工复核；界面上的「AI 建议 / 待确认」标记就是为此保留的
- 纯静态托管模式下，参与者信息收集采用「本机 + 扫码回执」：纯静态托管没有共享服务端，所以手机提交靠「同源实时同步（同一台电脑的另一个标签页 / 内置预览）」或「回执码 / CSV 带回来」两条路；换设备又不在同一网段时，请让参与者把回执码发回来粘一次；本机服务开着时（局域网 / 隧道）手机提交会直接落到本机 `generated/join/`，不用发回执码
- 二维码只做到版本 7（122 字节、纠错等级 M）：字段多、选项长时会自动降级——先丢掉标题与须知、再退成只带表单定义的链接；表单仍然放不下就退回「表单码」手工粘贴。链接里没有项目号时，同源预览靠本机已存表单归位，跨设备靠回执码 / CSV 带回
- 参与者明细与其他内容一样只存在浏览器本地，换机器请用「导出项目包」一并带走
- 服务默认只听 `127.0.0.1`；用 `DEMO2_HOST=0.0.0.0` 或 cloudflared 隧道时，非本机可匿名填写与提交，工作台静态界面允许加载；共享项目数据与管理接口需有效邀请凭据，服务端源码、共享存档文件和报名存档文件对非本机不可读（防火墙命令见「扫码填写怎么开」，隧道见 `docs/手机直传怎么开.md`）
- 发布到公网走静态托管（`tools/pack-static.mjs` → `dist/`）时没有后端：AI / 生图 / 上传模板解析 / 帮助页的技能包注册表都会置灰或显示未读取到，数据仍只存在各自浏览器里（见 `docs/静态托管怎么部署.md`）
- 画布是零依赖手写的（这是本项目「零构建」的非目标的一部分），所以没有成熟画布工具的那些体验：没有多选 / 框选（一次只能拖一张卡片，批量改要重复几遍）、没有对齐参考线与吸附对象、连线不能中途改接（要改就断掉重连）；撤销只覆盖画布上的改动（摆位 / 连线 / 引用勾选 / 增删卡片 / 收起），正文打字按输入框合并成一步，不做逐字撤销。卡片多到一屏放不下时，用「适应屏幕」看全局、用缩略图 / ⌘K / 「放大画布」跳或铺开——这是它的兜底路径。画布里的文字一律不可选（拖动是手势不是划词，免得拖一下拉出一片蓝色选区）：要复制正文请点卡片里的「复制文本」，或打开卡片配置窗在弹窗里选中


### 风险预案与演练闭环（2026-10）

- 风险卡直接发起关联演练；也可自定义场景，或将预设作为可编辑模板。准备阶段可调整风险关联、情境、模式、人员、资源、步骤顺序及通过标准。
- 确认开始后冻结方案。每步记录通过、发现问题、未验证或不适用；现场实测通过须填写证据，问题与不适用须填写原因。结束必须填写复盘，旧勾选记录保留为历史，不能推断为验证通过。
- 结束记录保留。预案先显示演练前快照、当前台账和拟修订内容，由用户明确确认更新；按风险编号关联，不按名称匹配。相同字段已被别人修改时停止覆盖。不会自动改评分、完成或验收任务。
- 问题步骤可分配实名责任人、截止时间和交付要求，创建一次关联整改任务，继续使用现有任务验收机制。共享项目分配须登录项目管理者账号，示例人员不能作为实名责任人。
- 复测创建新记录并关联前次演练，所有验证结果重新开始，旧证据与结论保留。项目包保留关联，Markdown 导出演练结果、证据、任务编号、预案修订和知识来源。
- AI 只生成待采用草稿，不覆盖人工步骤。沿用知识库目录选章机制，保留本次引用快照；支持不调用 AI 的完整手动流程。
- 只读前端与共享 API 均禁止修改。共享版本冲突沿用现有草稿保留机制；新版已结束执行记录服务端禁止删除或改写（复盘整改字段除外）。旧记录缺失模式、实名信息、证据时不补造。

使用示例见 [风险预案与演练使用指南](docs/风险预案与演练使用指南.md)。这是人工辅助演练与复盘系统，不连接现场传感器，也不自动判断真实事故、证据真实性或预案有效性。证据栏目前保存文字及已有材料编号/版本，附件仍在素材库管理。跨项目导入的人员编号可能不在目标名册内，应重新核实后分配。
