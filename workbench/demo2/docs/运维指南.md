# 校园活动工作台运维指南

适用版本：v1.0 正式版，功能基线 d39138e。更新日期：2026 年 10 月 12 日。

本指南面向负责安装、网络开放、配置、备份和版本更新的维护者。普通活动操作见同目录《用户手册》。以下命令均在仓库根目录的 PowerShell 中执行；本机目录为 `E:/CodexWorkplace/structured-thinking-workbench`，其他电脑使用实际目录。

## 1. 运行环境与启动管理

### 环境与最小启动

需要 Node.js 18 或更高版本、现代 Chrome 或 Edge，以及完整仓库文件。应用使用原生浏览器能力和 Node 内置模块，无需构建或安装额外运行依赖。

```powershell
node --version
node workbench/demo2/server.mjs
```

默认入口为 `http://127.0.0.1:4175/`，默认只监听本机。保持窗口运行；在该窗口按 Ctrl+C 停止。停止服务不会删除已保存的数据。

Windows 可双击根目录 `start.bat`，脚本检查后端与账号接口，处理占用端口的旧工作台进程，再打开浏览器。它不会主动结束占用端口的无关程序。`stop.bat` 用于停止对应工作台服务及监视进程。

启动脚本支持后端文件修改自动重载；直接用 Node 启动时，修改后端需要手动重启。切勿在使用中的项目上同时启动多个写入相同数据目录的服务进程。

### 自定义端口

需要换端口时，在同一窗口明确设置环境变量再启动，使用 Ctrl+C 停止：

```powershell
$env:DEMO2_PORT='4176'
node workbench/demo2/server.mjs
```

此时入口为 `http://127.0.0.1:4176/`。启动、停止脚本读取当前进程环境中的端口；仅修改 `.env` 不能保证双击脚本按新端口检查。更换网址后，浏览器本地存储也会切换，提前导出项目包并保留共享凭据。

### 启动后检查

```powershell
Invoke-RestMethod 'http://127.0.0.1:4175/api/health'
Get-NetTCPConnection -State Listen -LocalPort 4175
```

健康接口应返回 `ok: true`。`providers.deepseek` 和 `providers.yoshub` 只表示相应密钥已配置，不代表余额、权限或上游连接已验证。未登录访问 `/api/personnel/me` 返回 401 是正常认证行为；返回 404 则应检查后端是否过旧。

## 2. AI 与服务配置

### 配置文件

服务读取仓库根目录 `.env`，每行一个 `KEY=value`。进程环境变量优先于 `.env`；修改后重启服务。已有 `.env` 先备份并编辑，不要用示例覆盖真实配置。使用下面的字段作为正式版配置参考；密钥值由维护者填写：

```env
DEEPSEEK_API_KEY=
DEEPSEEK_MODEL=deepseek-chat
YOSHUB_API_KEY=
YOSHUB_API_BASE=https://api.yoshub.com
YOSHUB_IMAGE_MODEL=gpt-image-2
DEMO2_PORT=4175
DEMO2_HOST=127.0.0.1
# 可选：账号、共享与报名数据的持久目录
# DEMO2_DATA_DIR=E:/WorkbenchData/activity-workbench
```

| 配置项 | 作用 |
| --- | --- |
| `DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL` | 文本服务密钥和模型；文本接口使用 DeepSeek |
| `YOSHUB_API_KEY`、`YOSHUB_API_BASE` | 图像服务密钥和兼容接口根地址；变量名沿用项目配置 |
| `YOSHUB_IMAGE_MODEL` | 图像模型，本项目使用 GPT-image2，接口模型名为 `gpt-image-2` |
| `DEMO2_PORT`、`DEMO2_HOST` | 监听端口和地址 |
| `DEMO2_DATA_DIR` | 可选服务存档目录；不移动生成图片与浏览器数据 |

图像接口填兼容服务的根地址；文本服务使用 DeepSeek 默认接口。

未配置 AI 不影响手工编辑、任务、资源、导出和服务端账号协作。配置后的实际调用会消耗相应账户额度，由用户在界面主动触发；维护检查先用健康接口，必要时再进行小规模生成。

### 配置与凭据管理

密钥由服务端读取，不填写进浏览器材料、公开截图或项目 JSON。`.env`、账号存档、组织者凭据和真实人员资料分别作为私有数据保存，不随课程演示包或公开仓库分发。项目协作链接同样带访问资格，只发给对应成员；人员加入码与编辑邀请分开管理。

## 3. 局域网与跨网络协作

### 同一网络：电脑作为服务端

1. 保存并导出当前项目，停止原服务。
2. 用下面命令开放监听，再执行 `ipconfig`，选择当前 Wi-Fi 或以太网的实际 IPv4 地址。

```powershell
$env:DEMO2_HOST='0.0.0.0'
node workbench/demo2/server.mjs
```

3. 其他电脑或手机访问 `http://<IPv4>:4175/`，将 `<IPv4>` 替换为电脑地址。例如电脑地址为 `192.168.1.23`，访问 `http://192.168.1.23:4175/`。按需在 Windows 防火墙允许 Node 的专用网络入站访问。
4. 在“参与者”把访问地址改为可达网址，再生成二维码；为协作成员从正确网址重新复制邀请链接。服务人员使用同一主机的 `/staff.html`。
5. 保持服务电脑开机、网络连接及 Node 进程运行。校园或访客 Wi-Fi 可能隔离设备；地址正确仍不通时换允许互访的网络。

`127.0.0.1` 只表示访问者自己的设备；`0.0.0.0` 是监听配置，不是发给成员的访问地址。项目加入码只能用于加入，不能绕过共享项目编辑资格。

使用结束后停止服务，将进程环境改回本机再启动；若 `.env` 也配置了开放监听，同时改回：

```powershell
$env:DEMO2_HOST='127.0.0.1'
node workbench/demo2/server.mjs
```

### 不同网络：临时 HTTPS 入口

可另行安装 `cloudflared`。先保持 Node 在本机运行，再在另一个窗口执行：

```powershell
cloudflared tunnel --url http://127.0.0.1:4175
```

将命令显示的临时 HTTPS 地址提供给成员，重新生成邀请与二维码；两个窗口都应保持运行。临时地址重新启动后可能变化，旧链接须更新。实际可用性取决于所用网络与隧道连接。

当前后端支持远程加载页面，项目数据和管理操作仍按账号及邀请权限校验；普通参与者按开放表单提交。

### 长期托管

完整部署需要可持续运行的单个 Node 服务、持久数据目录、HTTPS 入口，以及定期备份。可选择提供 Node 运行环境的托管平台或云服务器；无需为课堂本机演示租服务器。部署时上传应用代码，私下设置环境变量，再检查账号、协作、报名及图片访问。

纯静态托管适合本地编辑与展示；完整协作采用 Node 服务。服务器实例重建前确认数据和生成图片均有持久保存。

## 4. 数据位置与备份

### 数据保存在哪里

| 数据 | 默认位置或载体 | 备份要点 |
| --- | --- | --- |
| 浏览器项目、界面状态与组织者邀请凭据 | 当前网址下的浏览器本地存储 | 导出项目 JSON；私下保留组织者凭据，避免清除浏览器数据 |
| 共享项目与版本 | `workbench/demo2/generated/shared/` | 与人员、报名存档一起备份 |
| 报名队列与短码映射 | `workbench/demo2/generated/join/` | 包含队列和项目映射文件，整体保存 |
| 账号、资格、班次、考勤 | `workbench/demo2/generated/personnel/` | 完整目录备份；人员导出不能替代账号备份 |
| 生成图片 | `workbench/demo2/generated/` 下的图片文件 | 保留原图，避免项目引用失效 |
| 私有配置与较大附件 | 根目录 `.env`、用户保存的原件目录 | 单独保护，记录存放位置 |

设置 `DEMO2_DATA_DIR` 后，`shared/`、`join/`、`personnel/` 改存到该目录的对应子目录。**生成图片仍保存到 `workbench/demo2/generated/`，不会随此变量移动。** 浏览器本地存储也独立存在。

### 备份时机与范围

每次集中协作结束导出项目；更新代码、换电脑、改网址、删除项目或课堂汇报前，做一次完整备份。活动执行期间按记录变化频率增加备份。保留至少一份最近可恢复的备份和一份较早版本。

完整备份包括四层：项目与各类业务导出；服务端存档；生成图片和外部原件；私有配置及管理凭据。Word、Excel、人员档案 JSON 都是成果或归档文件，不能单独恢复整套服务。

### 默认目录的备份操作

1. 在浏览器确认共享同步完成，导出当前项目、人员考勤、报名记录和必要材料。
2. 通知正在操作的成员暂停，停止 Node 服务，确保没有其他进程写入该目录。
3. 在仓库根目录执行以下命令。首次运行未产生目录时，只需保留已有项目导出。

```powershell
$backupRoot=Join-Path (Get-Location) ('backups/'+(Get-Date -Format 'yyyyMMdd-HHmmss'))
New-Item -ItemType Directory -Path $backupRoot -Force | Out-Null
if (Test-Path -LiteralPath 'workbench/demo2/generated') {
  Copy-Item -LiteralPath 'workbench/demo2/generated' -Destination (Join-Path $backupRoot 'generated') -Recurse
}
```

4. 另行保存 `.env`、浏览器组织者凭据和大附件，写下代码版本、端口、数据目录及备份时间。将备份复制到另一存储位置，检查关键文件可读，再恢复服务。

### 自定义数据目录的补充备份

仍需备份仓库内的 `generated/` 图片，并额外复制实际服务存档目录。例如：

```powershell
$serviceDataDir='E:/WorkbenchData/activity-workbench'
Copy-Item -LiteralPath $serviceDataDir -Destination (Join-Path $backupRoot 'service-data') -Recurse
```

这里的 `$backupRoot` 沿用上一段同一 PowerShell 会话创建的目录；先核对 `$serviceDataDir` 为真实配置位置。备份放在私有存储，不提交 GitHub。

## 5. 恢复、更新与回滚

### 恢复默认存档

先停止服务，核对备份来源、代码版本和配置。保留现有目录作为恢复前快照，再复制备份，避免直接删除当前记录。

下面是默认目录的恢复示例：将 `$restoreFrom` 改成已检查的备份路径，再执行。

```powershell
$restoreFrom='E:/WorkbenchBackups/20261012-180000/generated'
$targetDir='workbench/demo2/generated'
if (!(Test-Path -LiteralPath $restoreFrom)) { throw '备份目录不存在' }
if (Test-Path -LiteralPath $targetDir) {
  Rename-Item -LiteralPath $targetDir -NewName ('generated-before-restore-'+(Get-Date -Format 'yyyyMMdd-HHmmss'))
}
Copy-Item -LiteralPath $restoreFrom -Destination $targetDir -Recurse
```

若使用自定义数据目录，按相同原则恢复 `service-data` 至原 `DEMO2_DATA_DIR`，另外恢复仓库内图片；不要把两者混放。恢复私有配置后检查路径，启动匹配版本的代码。

原浏览器保留的草稿可能比备份新，也可能比共享版本旧。先导出本地草稿，再加载服务端最新项目，核对需要合并的内容。新电脑用有效组织者凭据恢复管理入口；项目包与账号存档分别按对应备份恢复。

### 恢复后的核对清单

1. 健康接口正常，原账号可以登录；项目列表和人员资格符合备份时间。
2. 检查任务责任人、交付版本、验收记录与共享版本。
3. 核对报名队列、排班、签到签退和工时，打开生成海报及凭证。
4. 使用单独测试项目验证写入和重新打开，不向正式项目添加测试记录。

人员、班次、考勤导出 JSON 用于归档；完整恢复使用服务存档备份。忘记密码时保留存档并核对账号，联系维护者处理。

### 更新代码与回滚

更新前保存本地改动并完成备份，停止服务，再拉取目标版本。遇到 Git 冲突先保留修改，人工解决，避免用强制清理覆盖本地材料。更新完成运行 `start.bat` 或重新启动 Node，刷新浏览器。

快速验收：登录 → 打开测试项目 → 查看任务、人员、材料版本 → 验证共享及报名 → 重新打开检查保存。AI 配置是否可用与核心功能分别检查。

开发者修改功能后可按影响范围运行以下检查；纯文档更新无需执行全套：

```powershell
node workbench/demo2/tools/selftest.mjs
node workbench/demo2/tools/integration-test.mjs
node workbench/demo2/tools/personnel-test.mjs
node workbench/demo2/tools/task-links-test.mjs
```

浏览器专项检查需要单独准备 Playwright 与浏览器环境。回滚时恢复上一代码版本及配套数据快照；先保留更新后产生的数据，避免直接丢弃新记录。Git 版本切换不会恢复浏览器存储或服务存档。

## 6. 故障排查

先记录报错、操作步骤和发生时间，导出能打开的项目；优先定位症状对应的层次，再修改配置。

| 症状 | 优先检查与处理 |
| --- | --- |
| 页面打不开 | 确认 Node 窗口仍在运行、端口正确，检查启动输出与监听状态 |
| 端口已占用 | 用端口检查确认进程；旧工作台进程用启动脚本处理，无关程序换端口或由其维护者停止 |
| 注册报 API 不存在 | 新页面可能连到旧后端；重启正确服务并刷新，检查账号接口不是 404 |
| 账号返回 401 | 会话可能过期或已退出；重新登录。会话有效期为 7 天 |
| 操作返回 403 | 检查项目邀请角色、账号资格和授权；由组织者重新发正确邀请或确认入组 |
| 文本或图片生成失败 | 查密钥、额度、模型名、接口地址与网络；健康标志为真也可能上游失败 |
| 手机无法连接 | 查实际 IPv4、开放监听、防火墙、网络隔离；不要使用本机地址或旧二维码 |
| 报名只显示本机保存 | 查看是否真正送达，保持页面联网重试；按回执码或 CSV 补录并检查重复 |
| 共享保存冲突 | 下载本地草稿，再加载最新共享版本并人工合并，不直接强制覆盖 |
| 批量排班失败 | 查整组资格、技能、跨项目时间冲突、资源状态与峰值；整组失败不产生部分班次 |
| 更新后材料或账号缺失 | 检查网址是否变化、原浏览器数据、数据目录环境变量及所用存档版本 |
| 海报无法显示 | 检查项目引用和原图片是否同时恢复；自定义数据目录不包含仓库内生成图片 |

### 日常维护最小清单

活动前：确认服务版本、账号登录、实际访问地址、二维码、邀请、资源与应急材料；完成一次备份。活动中：保持服务电脑和网络运行，检查同步、报名送达及未签退记录。活动后：核对任务验收、考勤、决算和资源归还，导出成果并备份，再关闭收集和归档项目。
