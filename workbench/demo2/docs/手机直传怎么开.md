# 手机直传怎么开（cloudflared 隧道）

这份文档只解决一件事：**让参与者的手机扫码填写，提交后 2–3 秒直接进你电脑上的工作台**，不用把回执码发回来。

如果你只是想让手机能填（同一个 Wi-Fi / 手机热点），看 README 的「扫码填写怎么开」前 3 步就够，不需要这份文档；
下面这套是**手机不在同一个网络**（人不在旁边、用流量、跨网段）时用的。

## 先说清楚它是什么

电脑上的 `server.mjs` 默认只监听 `127.0.0.1`，只有本机能连——所以手机连不上，这是默认的安全状态。

`cloudflared` 是 Cloudflare 提供的一个命令行工具：它从你电脑**主动往外**连一条加密通道，换回一个 `https://xxx.trycloudflare.com` 的公网地址。因为是你往外连，所以**不用公网 IP、不用动路由器端口映射**；关掉这个命令，地址立刻失效。

关键点：`server.mjs` 会把「从隧道进来的请求」当作**非本机**处理，只会放行下面这几条路——

| 外面能访问的 | 作用 |
| --- | --- |
| `GET /signup.html` | 手机填写页 |
| `GET /core/qr.js`、`GET /core/signup.js` | 填写页要加载的两个脚本 |
| `GET /api/signup/form?p=<短码>` | 按短码取表单定义 |
| `POST /api/signup/submit` | 提交一条填写结果 |

其余一律 `403`：工作台页面、`app.js`、`styles.css`、`/api/structure`、`/api/material`、`/api/image`、`/api/template`、`/generated/` 图片、`/api/signup/link`、`/api/signup/queue` 都出不去。AI Key 始终只在服务端，外部拿不到。

> 一句话：隧道只把「一张填写页 + 一次提交」放出去，别的都留在本机。

## 逐步操作（照抄即可）

### 第 0 步：装 cloudflared（只需一次）

先试最省事的（Windows 10 以上自带 winget）：

```powershell
winget install --id Cloudflare.cloudflared
```

装完关掉当前 PowerShell 重新开一个（让 PATH 生效），执行 `cloudflared --version` 能看到版本号就算成功。

装不上（公司/校园网络拦了 winget，或提示找不到包）就去官网手动下载：

- 打开 <https://github.com/cloudflare/cloudflared/releases/latest>
- 找到 `cloudflared-windows-amd64.exe`，下载后改名成 `cloudflared.exe`，放在一个固定目录（比如 `C:\tools\cloudflared.exe`）
- 后面命令里的 `cloudflared` 就换成这个完整路径，例如 `C:\tools\cloudflared.exe tunnel --url http://127.0.0.1:4175`

### 第 1 步：窗口 1 启动本机服务

在仓库根目录执行（默认只监听本机，这是对的，隧道会从本机转发进来）：

```powershell
node workbench/demo2/server.mjs
```

看到 `Demo2 listening at http://127.0.0.1:4175/` 就行，**这个窗口不要关**。启动日志里也会打印下面那条隧道命令供你抄。

### 第 2 步：窗口 2 启动隧道

**另外开一个** PowerShell 窗口（不要占用窗口 1），执行：

```powershell
cloudflared tunnel --url http://127.0.0.1:4175
```

等十几秒，它会在一个方框里打印一条给你的地址，形如：

```text
https://calm-sunset-a1b2.trycloudflare.com
```

**这就是给手机用的地址，复制它**（免费版每次启动都不一样，属正常）。这个窗口同样不要关。

### 第 3 步：把地址填进工作台

打开工作台（<http://127.0.0.1:4175/>）→ 左侧「参与者」→ 打开「开启收集」→ 在「访问地址」里粘上刚才那条 `https://…trycloudflare.com`（站点根形态即可，不用带 `/signup.html`）→ 点「重新生成二维码」。

此时二维码里只有 4 位短码（例如 `#p=k7f2`，几十字节），表单定义由本机服务按短码提供给手机——所以再长的隧道域名也装得下。

### 第 4 步：手机扫码填写

手机（流量或任意 Wi-Fi 都行）扫码 → 填写页 → 提交。提交成功后页面上会写「**已直达组织者电脑 ✓**」。

回到工作台「参与者 → 明细」，2–3 秒内就会出现这条记录（来源标为「填写页」）；工作台没开在这一屏也会自己拉。

### 第 5 步：演示完就收

两个窗口各按一次 `Ctrl+C`（先关隧道、再关服务，顺序无所谓）。隧道地址随进程消失；本机数据不受影响。

## 安全边界（这段是重点）

- **隧道是出站连接**：不用公网 IP、不用端口映射、不用改防火墙；命令一停地址就废。
- **不是「整站上线」**：外部只拿到上表那几条路，工作台与 AI 接口一律 403。
- **地址本身是公开的**：任何拿到这条 `https://…trycloudflare.com` 的人都能打开填写页并提交。它是「一张表单」，不是登录入口；演示完请立刻关掉隧道，别长期挂着。
- **提交有上限**：同一来源每分钟最多 40 条，单个项目最多 800 条，单次请求体上限 8 KB、回执码上限 1500 字符；超了会回 429 / 413，界面上会提示改用回执码或 CSV。
- **落在哪里**：手机提交按行落在 `workbench/demo2/generated/join/<项目>.jsonl`，项目与短码的对照表在 `generated/join/projects.json`；`generated/` 已在 `.gitignore` 里，不会被提交、也不参与静态托管打包。
- **短码只有 4 位**、重启 `server.mjs` 后登记表会重新生成（短码可能变），所以重启后回工作台「重新生成二维码」再扫。

## 常见问题

| 现象 | 原因 / 怎么办 |
| --- | --- |
| `cloudflared` 不是内部或外部命令 | 第 0 步没成功或没重开窗口；改用下载下来的 `cloudflared.exe` 完整路径 |
| 手机打开地址是 403 | 访问的不是填写页那几条路（例如手动敲了 `/`）；正常应该扫二维码或直接开 `https://…/signup.html#p=短码` |
| 手机提交后工作台没进表 | ① 工作台要开着（它每 2.5 秒拉一次）；② 确认工作台里当前项目就是扫码那个项目；③ 服务重启过就重新生成二维码（短码变了） |
| 提交后显示「带回执码」而不是「已直达」 | 说明这次提交没能直传：或是走静态托管 / 离线那条路（比如用了 `dist/`、隧道没开），或是**这张二维码没带项目号 / 短码已过期**。让组织者回工作台「参与者」点一下（工作台连着服务时自己登记短码、2–3 秒后二维码换成带短码的版本），重新扫一次即可；也可以直接把回执码发回来粘一次 |
| 二维码扫不出来 | 先点「重新生成二维码」；隧道地址填错（带了 `/signup.html`）也能用，但短码模式下建议只填站点根 |
| 页面提示 429 / 413 | 提交太密或单条太大：等一分钟，或让参与者改用回执码 / CSV 导入 |

## 和另外两条路的关系

| 你的场景 | 用哪条 |
| --- | --- |
| 只是自己演示、同一台电脑 | 「内置预览」或另开标签页，靠同源实时同步，不用任何网络设置 |
| 手机就在旁边、同一个 Wi-Fi / 热点 | README「扫码填写怎么开」第 1–3 步（局域网），提交同样直达本机 |
| 手机不在同一网络 | 本文档（cloudflared 隧道） |
| 只想让别人看内容、不想开服务 | 静态托管（`tools/pack-static.mjs` → `dist/`），见 `docs/静态托管怎么部署.md`；填写页会退回「回执码 / CSV」 |
