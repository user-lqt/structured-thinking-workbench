# 服务人员账号、任务轮班与统一资源管理

更新：2026-10-11。本次把「人员数量」细化为账号关联的服务人员名册、任务和班次；物料与设备清单改为从资源台账生成。课堂仍可本机运行，无需部署公网。

## 负责人开通

1. 运行 `node workbench/demo2/server.mjs`，打开 `http://127.0.0.1:4175/`。
2. 先注册 / 登录个人账号。账号为 3–60 位字母、数字或 `_.-`；密码为 8–128 位。注册选择「组织活动」，填写本人姓名、联系方式、学院 / 部门、技能与可服务时段。
3. 登录后进入项目选择，再新建或打开项目；系统自动启用共享存档、开通人员管理，并把账号资料登记为负责人，无需在资源页重复登录或填写。已有共享项目使用原组织者凭据；已有人员管理的项目保留原账号归属。
4. 进入「人员与资源 → 服务人员」查看名册与考勤；在「全周期任务」从任务行安排人员。再次打开同一项目只更新本人基本资料，不新增重复行，不改变项目资格、授权与考勤。修改账号资料可从右上角菜单或个人任务页进入。
5. 将页面显示的项目加入码和 `http://127.0.0.1:4175/staff.html` 给演示中的志愿者会话。不同人用不同浏览器或隐私窗口，避免同浏览器标签共用登录状态。

本地演示身份保留在登录页的折叠入口，用于无账号的离线查看；正式服务人员从主登录入口进入。服务账号使用服务端密码验证，本地角色不能提升服务权限。开通后的原项目负责人账号不能由另一账号拿邀请凭据直接替换。

## 志愿者加入与个人任务

1. 打开工作台主登录页，注册时选择「参加服务」并填写个人资料；登录后进入个人任务页。也可直接从 `staff.html` 登录。
2. 登录后选择并打开负责人已开放的项目。首次打开输入加入码，系统把账号资料自动录入项目名册，不再重复填写项目内资料；有效协作邀请也可授权首次登记。
3. 名册立即增加一条「待确认」记录；负责人确认后变为已加入。再次打开已加入项目无需加入码、不重复登记。本人可更新账号资料，下一次打开时同步到项目，考勤流水保留。组织者项目库也会显示尚未存入本机的可加入服务项目。
4. 项目负责人可以授权另一位已加入人员为现场管理者；志愿者不能自行选择管理权限，现场管理者不能再向别人授予管理权限。
5. 被分配后，“我的任务”显示本人岗位、关联的 WBS 任务、时间、地点、执行要求、预留资源和工时。普通志愿者不接收其他人的联系方式、名册、任务或加入码。
6. 接受任务，到岗签到，离场签退，最后报告完成。任务完成不会自动把整个 WBS 任务标成完成；活动负责人仍要核对整项交付。

账号可加入多个项目，所选项目会在浏览器记住；换设备重新登录后仍能看到服务端保存的安排。密码使用带盐 scrypt 哈希，登录会话有效 7 天，退出会话立即在服务端失效。当前未提供邮箱找回密码或单点登录。

## 任务与轮班

负责人在「全周期任务」点击任务行的「安排人员」，系统自动选中该任务，再从已确认名册选择人选，设置岗位、计划开始 / 结束、地点、必要技能和执行说明，并按需要预留物资与资源。也可在分配区先选择任务，再选择人员；未选任务时人员选择不可用。独立服务入口中的管理者采用同样的任务优先顺序。

任务行显示已经安排的人员和班次数，分配区展示该任务的既有班次，并在选人后显示技能、可服务时段与未完成班次数。人员使用复选框，支持一次勾选多人、全选和清空。一次保存为每名人选创建独立班次，接受、打卡和报告分别记录；保存后保留所选任务便于继续安排，并清空已提交人选。编辑中的表单在后台刷新时保留，提交失败显示原因并保留所有勾选。

物资填写「每人数量」，总预留 = 每人数量 × 所选人数，页面随选择更新。后台先校验整组人员的资格、技能、时间冲突和资源同时段峰值，再一次保存；任一人不合格或库存不足，整组不落盘，不产生部分安排。旧单人接口仍兼容。

安排人员之后，所选任务的「任务执行与验收」在分配区直接展示状态、下一步说明及适用操作。任务人员列提供「查看任务 / 提交与验收」，详情中的操作位于班次记录上方。人员从「我的任务」接受班次、打卡并填写班次执行报告；整项任务依次开始执行、选择已确认的实际交付版本提交验收，再由组织者验收通过或退回。排班保存本身不改变生命周期，班次结束也不自动验收任务。

任务安排区及人员名册提供「载入 10 名示例人员」，包含协调、签到、宣传、摄影、后勤、接待、主持、设备、财务、应急岗位，姓名和资料明确标示例。重复点击不重复创建。示例无真实联系方式和登录账号，不能被授权管理者或用作实名责任人；管理者可模拟接受班次、打卡、提交报告，记录注明示例操作，不自动验收任务。「移除未排班示例人员」只删除未被使用的示例，已安排、已结束和已取消的历史班次均保留；正式课堂项目可按需载入。

班次必须结束晚于开始，单班不超过 24 小时；跨午夜时选择正确的结束日期。时间以浏览器时区转换为带时区的时间戳存储。同一人员在同一或不同项目中不能有同时段班次；相邻班次可以接续。必要技能从人员登记的技能中校验，可服务时间文本则供负责人人工核对。

同一资源按重叠班次的峰值检查，不能把前后顺序使用的资源简单相加。净可用 = 登记库存 − 已借出；维修中和报废资源不能被预留。已经有考勤流水的班次不能改写，以防历史记录对应错误；应签退后取消计划或另建班次，流水继续保留。

班次预留和台账的「计划需求」是两种不同口径。计划需求是活动总体需求，班次预留是时间段使用安排，不相加当成总占用。修改库存后负责人应重新核对既有安排；系统在新排班时检查最新共享台账。

## 打卡与工时

每次打卡由服务器记录时间，不能用客户端提供的时间覆盖。每条流水有账号、操作者和本人 / 管理者代打卡标记。未签到不能签退；重复发送同一个操作编号不会重复增加工时。修改资料、退出账号或重启服务不会丢失已保存记录。

服务工时为每段有效「签到 → 签退」的累计，不包含中间离场时间；未签退时段显示当前在场时长，单独列示。本人同一时刻不能在多个班次或项目同时在场。停用人员不能新签到，但已有在场班次仍允许签退，避免遗留记录无法结束。系统记录实际打卡，不以计划班次自动伪造出勤；未提供 GPS 定位或防代签证明。

这套服务人员班次考勤与普通参与者表单考勤分别存储。旧工作人员表单记录不会自动按姓名关联为账号，以免重名误配；新服务排班以账号名册为准。

## 统一资源与物料清单

「人员与资源」分为「服务人员」和「物资与资源」两个区域。服务人员区维护账号名册、资格与授权、资料、本人班次和全部考勤，不含发票功能。旧项目的人员数量保留在服务人员区的「历史人员需求汇总」，不自动伪造账号或实际出勤。

物资与资源区统一维护场地、设备、物料、经费和车辆，记录已借出、单价、存放地点、采购 / 来源和状态。新增、AI 提炼、示例台账及发票关联下拉框均不再包含人员类型。载入示例仅追加缺少的示例，不覆盖已有库存或凭证。资源台账 Markdown 导出分开历史人员汇总和物资明细，人员表不带发票列；项目 JSON 保留全部旧数据。

「过程材料」的物料清单卡片提供最新台账的只读查看和 Word / Excel / Markdown 导出，以及「去管理资源」入口。它不再独立 AI 生成或编辑，以防存在两套数量。资源页也可直接导出物料与设备清单 Excel；其费用为计划需求 × 单价的估算，不是决算。

采购发票入口在「人员与资源 → 物资与资源」工具栏：选择对应资源，点击「提交发票」；也可在资源行右侧「采购发票 / 凭证」点击上传或拖入文件。人员不会出现在发票关联列表中。「过程材料」的物料清单跳转会直接打开物资区。每项最多 6 份，≤400 KB 的原件随项目包与共享存档保存并可下载，较大文件仅记录名称、原件需要另存。资源编号用于关联，调整名称、数量或排序不会移除发票。物料清单与资源台账导出带凭证文件名，不把原件嵌入 Excel；原件从台账下载或随项目 JSON 备份。

预算与决算表原有的逐行发票入口仍在「过程材料」；资源页有跳转按钮。旧物料清单的发票随原稿备份保留，有原件的可在资源页「旧物料清单发票备份」下载；导入台账时按原表行迁入对应资源，相同资源合并附件且不重复导入。

原有物料清单自动备份为项目内 `resourceMaterialBackup`。在资源页点击「旧物料清单导入台账」，系统识别名称、数量、单位和单价，确认后导入；数量视为计划需求，库存先置 0 等待人工核实，相同名称和单位的已有行跳过。没有可识别表格时手动补录，旧正文仍可导出。旧参考表和模板仍保留，资源清单导出使用统一台账结构。

## 备份与运维

- 项目 JSON 保存统一资源台账与旧清单备份，不包含服务账号的密码或个人会话。
- 负责人在人员名册上方导出「人员 / 班次 / 考勤 JSON」，保存服务记录与操作日志。
- 服务端人员账号、项目资格、班次和流水在 `generated/personnel/`，或 `DEMO2_DATA_DIR/personnel/`。浏览器项目包不能恢复这套账号；完整运维备份需先停止 Node 服务，再一起备份此目录和 `shared/`。
- 导出的人员档案仅提供复核与归档，尚未提供将档案重新导入账号系统的功能。服务存档不能从网页静态路径读取。
- 当前适合单个 Node 进程和本机课堂演示。纯静态页面不能注册账号、排班或记录服务打卡；真实公网登录需另行配置 HTTPS 与持久存储。
