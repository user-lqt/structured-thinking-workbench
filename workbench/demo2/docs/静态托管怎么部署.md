# 静态托管怎么部署（新手版）

面向完全没部署过网站的人。所有命令都在**仓库根目录**（`结构化思维与AI`）执行，全程只有一条命令。
一句话结论：**打包一次 → 把生成出来的 `dist/` 拖到托管商 → 得到一个公网网址。**

## 30 秒版本

```powershell
node workbench/demo2/tools/pack-static.mjs
```

看到 `✓ 不含 .env、server.mjs、tools/、docs/` 就成功了，产物在 `workbench/demo2/dist/`。
然后把 `dist/` 里的内容上传到 Cloudflare Pages（第 3 节，推荐）或 GitHub Pages（第 4 节）。

## 1. 先说清楚：静态托管是什么，什么能用什么不能用

静态托管就是「把一批不会变的文件（HTML / CSS / JS）放到一台一直开着的机器上，谁访问都拿到同一份」。
托管商只负责发文件，**没有后端**——所以原来由 `server.mjs` 提供的接口就都没有了：

- **照常可用**（全部在你或访问者的浏览器里跑）：12 个视图、项目向导、问答式补全（本地题库 + 本地成稿）、任务分解与甘特、阶段门禁与自动打勾、风险台账与演练、方案比选、海报设计器、素材库、Word / Excel 导出、二维码与参与者收集、项目包导入导出。
- **会变灰或提示离线**（需要 `.env` 里的 API Key，只有 `server.mjs` 才会调用）：AI 生成、AI 追问、AI 生图、上传 Word 模板解析。这不是坏了，是设计内的降级。
- **会显示「尚未读取到技能注册表」**：帮助页的「技能包一览」。技能注册表由服务端读取，静态托管下读不到，其余照常。

还有一条最容易误会的事：**数据存在每个访问者自己的浏览器里**（localStorage）。
你填的项目，别人打开你的网址看不见；别人填的，你也看不见。想让别人看到内容，用「导出项目包 / 导出全部档案」把文件发过去。

## 2. 打包

```powershell
node workbench/demo2/tools/pack-static.mjs
```

会打印发布清单，然后给出四条结论，例如：

```
✓ 共 34 个文件 / 789.5 KB
✓ index.html、signup.html 与脚本里的 31 个相对引用，产物里都在
✓ 不含 .env、server.mjs、tools/、docs/
✓ 产物里 34 个文件与清单完全一致，没有多余文件
```

四条里任何一条变成 ✗，脚本都会以退出码 1 结束，并告诉你差在哪：引用缺文件、混进禁品、或产物里多出清单之外的东西（多半是上次的旧文件没清干净）。

常用开关：

| 命令 | 作用 |
| --- | --- |
| `node workbench/demo2/tools/pack-static.mjs --dry-run` | 只打印清单，不写任何文件 |
| `... --out 某目录` | 换个输出目录（默认 `dist/`） |
| `... --with-skills` | 连 `skills/` 里的技能包一起带上（可选，静态托管下界面用不到） |
| `... --help` | 看用法 |

这个脚本同时是**发布前检查**：清单是白名单，逐个写出来的，所以 `.env`、`server.mjs`、`tools/`、`docs/`、`generated/` 一律不可能被打进去；
把输出目录指到 `core/`、`views/`、`docs/` 或项目本身也会被直接拒绝，避免把自己覆盖掉。

`dist/` 已经在仓库 `.gitignore` 里，不会污染提交记录。

### 想在本机先空跑一遍（可选）

不折腾也行——`dist/` 里就是刚才你刷新页面看到的那批文件。真要空跑，装了 Python 的话：

```powershell
python -m http.server 5000 --directory workbench/demo2/dist
```

然后浏览器打开 `http://127.0.0.1:5000/`。注意：**不要用 `server.mjs` 预览 `dist/`**，它服务的是源码目录，不是产物目录。
另外直接双击 `dist/index.html`（`file://` 方式）不行，浏览器会拦掉取示例数据那一步。

## 3. 方案一：Cloudflare Pages（推荐）

免费、免备案、自带 HTTPS，给一个 `xxx.pages.dev` 的网址。步骤：

1. 打开 <https://dash.cloudflare.com/sign-up> 注册（邮箱 + 密码，收信点一下验证）。
2. 登录后左侧找 `Workers & Pages` → `Create`（创建）→ 切到 `Pages` 标签 → 选 `Upload assets`（上传静态资源）。
3. 填项目名：只能小写字母、数字、连字符，比如 `activity-workbench`。它会变成网址前缀 → `activity-workbench.pages.dev`。
4. 把 `workbench/demo2/dist/` **里面的内容**整个拖进上传区（也可以直接把这个 `dist` 文件夹拖进去，Pages 认它）。关键是别漏文件、别多套一层文件夹。
5. 点 `Deploy site`，等十几秒，拿到 `https://<项目名>.pages.dev`。这就是公网网址，手机也能打开。
6. 以后改了源码要更新：重新跑一遍第 2 节的打包，进这个项目 → `Create new deployment` → 再拖一次同样的文件。网址不变。

界面文字可能随版本微调，认这几个关键词就行：`Pages` / `Upload assets` / `Deploy` / `Create new deployment`。
免费额度对课程演示绰绰有余（具体额度以官网为准）。

## 4. 方案二：GitHub Pages

1. 注册 GitHub，右上角 `+` → `New repository`，填仓库名（比如 `activity-workbench`），可见性选 **Public**（免费账号的 Pages 只支持公开仓库）→ 创建。
2. 进仓库 → `Add file` → `Upload files`，把 `dist/` 里的内容整个拖进去 → `Commit changes`。
3. 仓库 `Settings` → 左侧 `Pages` → `Source` 选 `Deploy from a branch` → `Branch` 选 `main`、目录选 `/ (root)` → `Save`。
4. 等 1–2 分钟，刷新这个页面，会显示网址：`https://<你的用户名>.github.io/<仓库名>/`。

两点注意：

- 网址里带 `/<仓库名>/` 这种子目录前缀**不是问题**：参与者里的「访问地址」保持**留空**，二维码会自动跟随当前网址（子目录托管已经专门测过）。
- 国内访问 `github.io` 有时不稳定；只在本校演示、想要稳一点，用方案一。

## 5. 上线后自查清单

- 打开网址 → 直接进工作台，先登录（随便填名字即可，这是本地演示用的身份）。
- 「帮助」→「试试示例项目」能载入 → 说明 `samples/` 带上了。
- AI 类按钮点不动、提示离线 → 正常，见第 1 节。
- 手机扫二维码：现在是 `https`，相机扫码能直接打开；「访问地址」留空即可。

## 6. 这些不要上传

`.env`（在仓库根，里面是 API Key）、`server.mjs`、`tools/`、`docs/`、`generated/`、`node_modules/`。
打包脚本已经按白名单挡掉了，正常走第 2 节就不会带上它们。

## 7. 常见坑

| 现象 | 原因 / 怎么办 |
| --- | --- |
| 打开是 404 或一个文件列表 | 上传时多套了一层文件夹；入口必须是根目录下的 `index.html` |
| 页面空白、点按钮没反应 | 少传了 `core/` 或 `views/` 里的文件；重新打包、整体重传一次 |
| 样式全丢（纯文字） | 少传了 `styles.css` |
| AI 按钮是灰的 | 预期行为：静态托管没有后端 |
| 换了网址后项目不见了 | 数据跟着域名走，换域名就是新的空库；用「导出项目包」搬过去 |
| 手机扫码打不开 | 用 `https` 网址（两个方案都给），二维码里的「访问地址」留空 |
| 想绑自己的域名 | 得备案；课程演示直接用 `*.pages.dev` 免备案 |

## 8. 数据在哪、怎么带走

所有项目、参与者记录、素材都存在**当前域名下的浏览器 localStorage**里：清浏览器数据 = 删库，换域名 = 换库。
所以建议阶段性用「导出项目包」（单个项目）或「导出全部档案」（整库）留档；换电脑、换网址时也是用这两个文件导入还原。
