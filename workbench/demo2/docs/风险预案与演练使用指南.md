# 风险预案与演练使用指南

## 建议演示：签到网络中断

1. 登录管理者的服务账号并打开项目。进入“风险预案”，找到自己的“签到网络中断”风险，点击“对此风险发起演练”。
2. 在准备页选择“桌面推演”，填写情境“连续两次扫码失败”。选择主持人和参与人员，记录分工，确认升级路径与中止条件。
3. 将处置过程分成三步：确认网络状态；启用纸质名单；网络恢复后补录。分别填写责任人、所需资源和通过标准，例如“2 分钟内取出名单”“补录后无重复签到”。步骤可增加、删除和上移。
4. 如需 AI，先在知识库勾选适用资料，点击“AI 起草建议”。阅读草稿后选择追加或丢弃。AI 没有执行演练，也不能替你填写通过结论。
5. 点击“确认方案并开始”。逐步讨论或实际验证，记录结果。本次发现“纸质名单未打印”，将第二步选为“发现问题”，写明原因；未测试的步骤保留“未验证”。
6. 填写复盘结论后“结束并复盘”。这一步只结束本场演练，不会宣称风险消除、自动修改预案或验收任何任务。
7. 在预案修订区对比演练前、当前台账和拟修订内容。补充“活动前打印纸质名单并指定存放位置”，确认更新。风险改名不会破坏关联；如果他人修改了相同字段，系统会阻止覆盖。
8. 在问题步骤下指定真实责任人、截止日期、交付要求“名单打印照片与存放位置说明”，点击“创建整改任务”。到任务页执行、提交实际交付版本，由组织者验收。
9. 回到演练，点击“基于本场发起复测”。新场次保留原场次链接，结果全部回到未验证。选择“现场实测”，验证取名单时间并填写实测证据。原记录仍可查看。
10. 导出演练 Markdown，或导出整个项目包保存完整数据。课堂陈述应区分桌面讨论结论与现场实测证据。

## 其他入口

- “自定义演练”：从空白场景开始，可选择关联已有风险。
- “使用模板并编辑”：把预置方案复制到准备页，按当前项目改写；不会直接跑固定题目。
- “演练记录”：查看准备中、进行中和已结束场次，收起后可继续。已结束的执行记录锁定，需要新结论时发起复测。

## 常见情况

- 看不到实名人员：登录服务账号并进入同一项目，在“人员与资源”刷新名册。示例人员不作为整改实名责任人。
- 不能结束现场实测：检查通过步骤是否有证据，发现问题或不适用是否有原因，是否填写复盘结论。
- 不能更新风险：确认已关联风险且有实际修改；风险被删除或相同字段被他人修改时，应在风险页核实，不能按同名风险自动匹配。
- 旧记录显示未验证：过去的勾选仅证明有人填报“完成”，不能证明通过验证。历史备注仍保留。
- 共享提示冲突：先导出本机草稿，再载入共享版本核对。不要通过刷新掩盖未同步修改。

## 边界

风险矩阵是人工/AI 辅助评分，不是自动事故检测。演练不证明真实环境一定安全。系统不会检查照片或说明是否真实，也不会代替管理者验收。AI 服务不可用时，所有场景编辑、执行记录、预案修订和整改流程仍可手动完成。
