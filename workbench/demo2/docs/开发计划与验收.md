# 工作台开发计划与验收标准

> 本文件是工作台自身的搭建过程材料，记录设计取舍、迭代计划与验收口径。

## 一、目标

把工作台从「两张结构化表 + 风险台账」扩展到覆盖 **策划—筹备—执行—收尾** 全周期的活动管控台：

1. 全周期管控：每个阶段都有任务、检查点（阶段门禁）、产出物与责任人。
2. 中间产物齐全：每类产出都由一个 skill 契约驱动，可生成、可编辑、可导出。
3. 风险闭环：识别 → 评分 → 分级 → 预案 → 复盘，并检查覆盖度。

## 二、范围与约束

- 改动范围：`workbench/demo2/` 之内，不涉及仓库其他目录。
- 技术约束：零构建、零运行时依赖，只用浏览器原生能力与 Node 内置模块。
- 离线可用：未配置 API Key 时，编辑、导出、海报生成等全部功能仍可用，仅 AI 按钮不可用。

## 三、信息架构

| 视图 | 作用 |
|---|---|
| 总览 | 阶段进度、关键节点倒计时、风险分布、待办与缺口提醒 |
| 项目信息表 | 事实区 + 产出配置，AI 只补空白不覆盖手改 |
| 全周期任务 | 任务分解表 / 进度甘特 / 阶段检查点 三种视图 |
| 方案比选 | 结构化决策矩阵：多方案 × 多准则加权评分，输出决策结论 |
| 风险预案 | 风险台账、5×5 矩阵、分级响应、覆盖度检查 |
| 过程材料 | 按阶段分组的 21 类产出，逐份生成 / 编辑 / 导出 |
| 素材库 | 多模态素材（图片 / 文本 / 链接）登记与引用 |
| 帮助 | 使用说明、运维指南、常见问题清单 |

## 四、数据模型

```
state = {
  version, project{basic,meta,outputs}, wbs[], risks[], riskCompliance[],
  options{selected,criteria,scores,decision,note}, assets[], poster{},
  materials{}, templates[], materialTemplates{}, gates{}, log[], view, ui{}
}
```

- 每条数据带 `source`：`user` 用户填写 / `ai` AI 建议 / `pending` 待确认。
- 合并规则：AI 只填空白与「待确认」，永不覆盖 `user`。
- 变更记录 `log` 记录关键动作，供收尾复盘与报告取证。

### 8.4 取舍与简化（如实说明）

- **身份不是鉴权**：没有账号体系、没有密码、没有服务端校验；角色只存在浏览器里，仅用于演示权限边界。服务端接口不校验身份。
- **多项目是本地多文档**：每个项目一个 `localStorage` 文档，不做跨设备同步；项目卡片上的进度快照只反映该项目最近一次保存。
- **演练是离线脚本推演**：场景与处置步骤是预置的固定脚本，AI 只负责「把场景落到本项目」，不生成新场景；结论需要人工复核。
- **备用能力检查用类别映射**：按场景风险类别映射到需要检查的资源类型，是简化规则，不是精确的资源排程求解。
- **AI 生图不做文字排版**：图像模型对中文文字不可靠，仍建议用海报设计器叠加文字。
- **只读门禁的边界**：门禁按控件特征（筛选 / 分段 / 导出 / 打开 / 关闭 / 下载放行，其余禁用）实现，新增视图若引入新的只读动作，需要在 `app.js` 的 `READONLY_ATTR` 里补充关键字。
- **本轮未做浏览器自动化走查**：当前会话没有可用的浏览器自动化工具，改为用假 DOM 对 11 个视图做 `render()` / `mount()` 冒烟（已借此定位并修掉一处只读门禁的健壮性问题）。
