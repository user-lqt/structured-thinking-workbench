# 多人共享、报名与考勤（2026-10-10）

## 启动与共享

在仓库根目录运行 `node workbench/demo2/server.mjs`，组织者在本机打开 `http://127.0.0.1:4175/`。

1. 创建项目或载入示例，在「项目库」点击「开启多人共享」。
2. 将弹出的协作邀请发给成员。「复制协作链接」可选择可编辑或只读邀请。
3. 手机或其他电脑访问时，先在「参与者 → 访问地址」填写可达的局域网或公网地址，再复制邀请。
4. 局域网模式：PowerShell 执行 `$env:DEMO2_HOST='0.0.0.0'; node workbench/demo2/server.mjs`；设备需连同一网络并可访问端口。公网可沿用已有反向代理或 cloudflared 隧道。
5. 只有邀请凭据有效的成员才能读取共享项目或调用相应接口。本地角色切换不会提升共享权限。

主界面顶端显示共享角色、版本和保存状态。编辑先存本机，约 650 毫秒后上传；其他浏览器约每 2.5 秒获取新版本。打字或运行卡片时不替换正在编辑的页面。

两个浏览器基于同一版本保存时，服务器只接受一个，另一个显示冲突并保留本机草稿。先点击「下载本机草稿」，再「载入共享最新版本」，将需要保留的修改重新补入。系统不会静默覆盖其他成员的版本。

组织者可「重置成员邀请」使旧成员与访客链接失效。「切为本机副本」会复制当前内容并转为独立项目；原共享项目及邀请凭据保留。请保留组织者原浏览器的数据，成员邀请不能恢复组织者权限。

共享数据保存在服务端 `generated/shared/`，报名流水在 `generated/join/`。可设置 `DEMO2_DATA_DIR` 指向持久化目录。当前实现面向一个 Node 进程；部署时使用持久磁盘，不要让多个独立进程并发写同一数据目录。纯静态托管没有共享后端，继续采用本机存档和回执导入。

## 工作人员与参与者

「参与者」页开启收集后提供两套链接与二维码：上方用于普通参与者；「工作人员 / 现场管理者考勤入口」只发给工作人员。服务端根据入口确定身份，不依靠手机自行填写的身份字段。

工作台中的组织者 / 成员 / 访客决定编辑权限；现场的工作人员 / 参与者决定考勤统计口径，两者互不替代。工作人员也需要在自己的考勤入口登记并签到。

明细可按身份、在场状态和姓名 / 学号 / 手机筛选。选中「工作人员」后补登的新行记为工作人员。管理者可在明细中代签到或代签退，流水保留操作者名称；工作人员刷新自己的页面可获取服务端最新考勤状态。

## 签到、签退与时长

手机登记后可签到，离场时签退；签退后可再次签到。未签到不能签退，重复签到不会新增一次在场。修改姓名、手机号等资料保留原考勤记录。

每条记录包括首次签到、最近签退、当前是否在场、每次进出流水和已确认时长。时长为每段有效「签到 → 签退」的和，中间离场时间不计入。还未签退的当前时段仅显示实时在场时长，单列展示，不计入已确认累计时间。时间精度为秒，界面按小时和分钟展示。

「本机已保存 / 正在发送」不代表已送达服务。页面收到服务端确认后才显示「已直达组织者电脑」。断网时可重试全部未确认回执；已经确认的回执不重复发送。回执备份包含报名和考勤事件。

关闭收集会关闭服务端两套表单；旧二维码不能继续提交。服务器拒绝未知项目、非法事件、过期字段定义和不符合必填 / 联系方式 / 选项要求的提交。

CSV 导出包含身份、时间、时长、记录号与考勤流水，导回可保留这些信息。JSON 导入导出保留完整记录，重复导入同一记录号不会翻倍。字段调整前保存版本映射；预设切换复用同名字段 ID，已收信息保留。旧版回执仍能读取。

## 卡片工作流

适合把同一份活动口径复用于多份材料：项目事实 → 活动执行口径 → 参与者通知 / 工作人员岗位简报。

「示例：口径 → 通知 / 岗位简报」建立三张卡片及依赖。可以手写正文或调用 AI；「运行全部」先执行上游，再执行下游。上游失败时跳过其下游，循环引用或失效引用会阻止运行。

卡片出稿后点击「写入过程材料」，对应材料进入主线材料清单，可继续编辑、导出及作为阶段检查的证据。已有正文被替换时会确认，并在 `workflow.materialBackups` 留一份原稿，随项目包导出。

```powershell
node workbench/demo2/tools/selftest.mjs
node workbench/demo2/tools/integration-test.mjs
node workbench/demo2/tools/pack-static.mjs --dry-run
```

另有真实浏览器脚本 `tools/browser-test.mjs`，使用开发环境已安装的 Playwright；不新增应用运行时依赖。通过 `DEMO2_PLAYWRIGHT_PATH` 指定该包目录，通过 `DEMO2_BROWSER_PATH` 指定 Chrome / Edge 程序。

本次通过 965 项离线断言、36 项接口集成检查与 21 项真实浏览器操作检查。

验证覆盖 215 个同一校园出口 IP 的并发提交、200 条分页边界、重试幂等、工作人员身份隔离、并发编辑冲突、邀请撤销、服务重启恢复，以及独立负责人 / 成员 / 访客 / 手机浏览器操作。

本次验证使用本机 HTTP 服务、模拟远程请求头和独立无头浏览器会话。尚未验证真实公网域名、实际手机扫码、学校网络或防火墙环境；没有部署到外部托管服务。AI 生成的编排逻辑使用模拟响应验证，未调用付费生成接口。
