# 人员与资源台账

## 何时使用

任务分解已完成，需要把「谁来做、用什么做、够不够用」结构化登记，用于排班、场地协调与经费核对时。

## 输入

项目信息表（人数、地点、备用地点、预算、约束）+ 任务分解表（阶段、任务、责任人角色）+
场地方案与预算表章节 + 已有资源名称清单（用于去重）。

## 输出契约

只输出一个 JSON 对象：

```json
{
  "resources": [
    {
      "name": "资源名称",
      "kind": "staff|venue|equipment|material|fund|vehicle",
      "phase": "plan|prepare|execute|close",
      "unit": "人|处|台|件|元|辆",
      "available": 1,
      "assigned": 0,
      "owner": "责任人角色",
      "note": "用途"
    }
  ]
}
```

## 字段要求

| 字段 | 要求 |
|---|---|
| name | 具体到可清点的对象，如「无线麦克风」而不是「音响设备」 |
| kind | 六类之一；人员=staff，场地=venue，设备=equipment，物料=material，经费=fund，车辆=vehicle |
| phase | 主要被占用的阶段 |
| available | 项目实际可支配数量；未知写 `待确认` 之外的最小可用估计，并在 note 说明 |
| assigned | 按任务需求累加出的占用量，不得超过实际需要的总量 |
| owner | 责任人角色，不写人名 |
| note | 用途或关键约束，如「含备用 2 台」 |

## 写作要求

- 至少覆盖人员与场地两类；有经费科目时必须给出 fund 条目
- 数量要与预计人数、场地规模、任务量逻辑一致，不得凭空放大
- 与已有资源同名的不要重复输出
- 只输出项目里真正会用到的资源，不要罗列清单式的通用物资

## 事实边界

- 不得编造实际不存在的场地、设备与供应商
- 不确定的数量写保守估计并在 note 标注「待核实」
- 不得编造经费科目与金额；金额未知时以预算上限拆分并标注

## 验收清单

- [ ] 输出是合法 JSON，无 Markdown 代码围栏
- [ ] 每条 kind 与 unit 匹配
- [ ] 未与已有资源重名
- [ ] 数量与项目规模逻辑一致

## 交付格式

- **主交付**：结构化表格导出（Markdown / CSV），由所在视图的导出按钮生成。
- **说明**：本技能维护的是工作台内的结构化数据，不产出可下载的文档；需要 Word / Excel 时，请到「过程材料」导出对应材料。
