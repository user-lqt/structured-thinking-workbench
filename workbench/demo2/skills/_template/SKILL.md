# <产出名称>

## 何时使用

说明触发场景。写清楚「用户说了什么」就应该加载这个 skill。

## 输入

说明生成前需要哪些信息（通常来自项目信息表与任务分解表），以及缺什么时必须停下来追问。

## 参考样例（可选输入）

输入里可能出现 `参考样例`：用户上传的往届样表或学校样表经工作台解析后的结果（`栏目` / `字段清单` / `表格表头` / `原文`）。有它时按四条处理：

- **栏目对齐**：输出的章节与字段以参考为准——参考里出现的栏目、表头、必填项一个都不能少，顺序也照它。章节标题由调用方注入，逐字照抄，不要改写、不要合并、不要自创。
- **口径对齐**：字段的写法、详略、单位与格式照参考（日期 `YYYY-MM-DD`、金额纯数字）。
- **内容不回填**：参考里属于别的事实的具体值（时间、地点、人名、电话、金额、单位、文号）一律不许照抄，必须换成当前项目的事实；没有就写 `待确认`。
- **只增不改**：当前项目有、参考没有的信息，放进对应栏目里，不要新开栏目。

输出前自查：参考里的每个表头与字段都能在输出里找到。

补充：工作台还有一轮「按参考重排」——把已经写好的正文交回来，要求按参考的栏目与表格列重排成成稿。这一轮的契约与首次生成一致（栏目照抄、字段逐条落、缺的写 `待确认`、不照抄参考里的事实），区别只是输入里多一份 `现有正文`：以它为准做重排与补全，不要推倒重写、不要丢内容。

## 输出契约

给出严格的 JSON 结构。只输出 JSON，不要 Markdown、不要代码围栏、不要解释。

```
{
  "title": "",
  "sections": [{ "heading": "", "body": "" }]
}
```

## 写作要求

- 结构、语气、篇幅要求
- 命名与格式（日期 `YYYY-MM-DD`、相对时间 `D-7`、金额纯数字）

## 事实边界

- 只能使用已提供的事实
- 缺失项一律写 `待确认`，不得编造

## 参考

- `references/<file>.md`：什么时候需要读它

## 验收清单

- [ ] 输出是合法 JSON，字段与契约一致
- [ ] 未编造任何人名、单位、数据
- [ ] 缺失项已标 `待确认`

## 交付格式

声明这份产出的默认交付格式（frontmatter 的 `deliverable`，取值见 `registry.json` 的 `deliverables`）：

- `word`：主交付 Word 文档（`.docx`），备选 Excel / Markdown
- `excel`：主交付 Excel 工作簿（`.xlsx`），一章一张工作表；备选 Word / Markdown
- `svg`：主交付矢量图（`.svg` / `.png`）
- `markdown`：结构化表格导出（Markdown / CSV）
- `none`：不产出可下载交付物

正文按 Markdown 写（标题 / 空行分段 / `-` 列表 / 管道表格），导出层会按这些结构拆成 Word 段落与 Excel 单元格；不要写 HTML、合并单元格或单元格内换行。
