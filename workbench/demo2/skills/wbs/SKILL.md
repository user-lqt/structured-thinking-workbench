# 全周期任务分解表

## 何时使用

项目信息表已建立，需要把「要办成什么」翻译成「要做什么」时。

## 输入

项目信息表的基本信息 + 已勾选的产出清单。未勾选的产出不得出现对应任务。

## 输出契约

```
{
  "rows": [
    {
      "phase": "plan|prepare|execute|close",
      "task": "",
      "owner": "",
      "due": "D-30",
      "duration": 2,
      "output": "",
      "depends": "",
      "milestone": false
    }
  ]
}
```

## 分解要求

- `phase` 只能取 `plan` / `prepare` / `execute` / `close`
- 四个阶段都必须覆盖，每个阶段至少 4 项任务
- 四个阶段的时间窗：策划 D-30 ~ D-15，筹备 D-14 ~ D-1，执行 D-Day，收尾 D+1 ~ D+7
- 任务粒度到「可指派、可验收」的级别，不要写成「做好准备工作」这类空话
- 任务之间不重复、不遗漏，遵循 MECE
- 时间用相对写法：`D-30` / `D-7` / `D-1` / `D日` / `D+1`
- `owner` 先写负责角色（策划组 / 宣传组 / 后勤组…），不知道人名时不要编造
- `depends` 填前置任务的任务名，没有则留空
- `milestone` 只标记「关键交付节点」（如方案定稿、宣传发布、彩排通过、活动开始、复盘会），全表 4–8 项，不要滥用

> 调用方会自动补 `status`（默认未开始）、`progress`（默认 0）与 `source` 字段，不需要你输出。

## 事实边界

- 缺少依据的负责人、金额、场地、单位一律写 `待确认`
- 不得编造具体人名、电话、数据

## 验收清单

- [ ] 输出是合法 JSON，顶层只有 `rows`
- [ ] 四个阶段都有任务，每阶段不少于 3 项
- [ ] 未勾选的产出没有对应任务
- [ ] 未编造人名，负责人为角色或 `待确认`

## 交付格式

- **主交付**：结构化表格导出（Markdown / CSV），由所在视图的导出按钮生成。
- **说明**：本技能维护的是工作台内的结构化数据，不产出可下载的文档；需要 Word / Excel 时，请到「过程材料」导出对应材料。
