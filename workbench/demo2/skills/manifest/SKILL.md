# 项目信息表

## 何时使用

用户刚建立项目、填写了活动基本信息，需要把零散输入整理成规范表格时。

## 输入

用户填写的基本信息（可能大量留空）。留空是允许的，不要追问，直接补成 `待确认`。

## 输出契约

调用方会注入具体的字段契约，字段以注入内容为准。顶层固定为：

```
{
  "basic":   { "<字段 key>": "值" },
  "outputs": { "<产出 key>": true },
  "notes":   ["补充说明，最多 3 条"]
}
```

## 产出配置的判定

`outputs` 决定后续阶段要生成哪些任务与材料，判定要克制：

- 只勾选本次活动的类型、规模、场地与审批要求确实需要的产出，**不要全部勾选**
- 依据：人数规模、是否户外、是否有外部嘉宾、是否需要现场秩序管理、预算是否需分项核算
- 拿不准的保持 `false`，宁缺勿滥
- 数量与复杂度匹配：小型活动 4–6 项，大型活动 8–12 项，不要凑满上限
- 四个「核心产出」（活动策划书、海报、风险应急预案、现场执行手册）对任何正式活动都应勾选

## 字段补充说明

- `venueBackup`（备用地点）：户外活动要给出方向，室内活动可写 `待确认`
- `coOrganizer`（承办 / 协办单位）：没有就写 `待确认`，不要推测
- `constraint`（已知约束）：写硬性限制，如不可占用某场地、不可使用某科目经费；没有则留空

## 事实边界

- 只能使用用户提供的事实
- 缺失的人名、单位、电话、金额、人数、依据一律写 `待确认`
- 不得推测或编造任何可核查的具体信息
- 可以补充结构性建议（目标受众、内容拆解方向），但必须属于通用经验

## 命名与格式

- 日期 `YYYY-MM-DD`；时间 `HH:mm`（24 小时制）
- 金额、人数写纯数字，不带单位与千分位
- 术语统一：用「主办单位」，不要写成「主承办」「承办方」
- 字段值控制在 40 字以内，除非确有必要

## 枚举

- 活动类型 ∈ {科技文化节, 运动会, 迎新系列, 竞赛选拔, 其他}
- 产出配置取值一律为布尔 `true` / `false`

## 验收清单

- [ ] 输出是合法 JSON，顶层只有 `basic` / `outputs` / `notes`
- [ ] 未编造任何人名、单位、金额、数据
- [ ] 拿不准的字段已写 `待确认`
- [ ] `outputs` 未全部勾选

## 交付格式

- **主交付**：结构化表格导出（Markdown / CSV），由所在视图的导出按钮生成。
- **说明**：本技能维护的是工作台内的结构化数据，不产出可下载的文档；需要 Word / Excel 时，请到「过程材料」导出对应材料。
