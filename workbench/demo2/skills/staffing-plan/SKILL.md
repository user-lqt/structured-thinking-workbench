# 组织分工与职责表

## 何时使用

需要确定谁来干什么、汇报给谁，或用户提到「分工」「职责」「组织架构」「谁负责」。

## 输入

项目信息表（人数、规模、审批要求）+ 任务分解表（任务与负责角色）。

## 输出契约

章节由调用方注入，逐字对齐。职责类内容一律用 Markdown 表格。

## 组织原则

- 层级不超过三层：总协调 → 组别负责人 → 组员
- 岗位必须覆盖任务分解表里出现过的所有负责角色，不得遗漏
- 每个岗位写清：职责、交付物、汇报对象、协同对象
- 需要跨组配合的环节要标出「协同岗位」

## 各章要求

| 章节 | 内容 |
|---|---|
| 一、组织架构与指挥关系 | 用缩进列表或表格表达层级，标出决策权归属 |
| 二、岗位职责表 | 岗位 / 职责 / 交付物 / 汇报对象 / 协同对象 |
| 三、协作与汇报机制 | 例会节奏、信息同步方式、异常上报路径与时限 |
| 四、志愿者需求与来源 | 岗位 / 人数 / 时段 / 能力要求 / 培训需求 |

## 事实边界

- 一律写**角色**（总协调 / 宣传组负责人），不写具体人名
- 志愿者人数未知写 `待确认`，不要编造分配数量
- 不得编造院系、班级、社团名称

## 验收清单

- [ ] 输出是合法 JSON，章节与注入模板逐字一致
- [ ] 岗位覆盖任务分解表中的全部负责角色
- [ ] 每个岗位有交付物与汇报对象
- [ ] 未出现具体人名
