# 风险应急预案

## 何时使用

风险台账已生成，需要形成正式预案文档提交或张贴时。

## 输入

风险台账（含等级、触发信号、措施、升级路径、责任人角色）+ 项目信息表 + 任务分解表。

## 输出契约

章节由调用方注入，逐字对齐。清单与分级用 Markdown 表格。

## 各章要求

| 章节 | 必须包含 |
|---|---|
| 一、风险识别与分级规则 | 分值算法、分级阈值、4T 策略说明、评估频次 |
| 二、风险清单与分级 | 高/中/低三张表，列：风险 / 阶段 / 挂靠任务 / 分值 / 责任人 / 触发信号 |
| 三、分级响应流程 | 高/中/低各自的发现—上报—处置—恢复步骤，含决策人与时限 |
| 四、应急联络与资源保障 | 联络角色表（含分机或频道，号码未知写 `待确认`）、物资与场地资源、外部支援 |
| 五、演练与复盘要求 | 演练时间与形式、复盘触发条件、记录要求 |

## 写作要求

- 内容必须与风险台账逐项对应，不得新增或漏掉风险
- 响应流程写成编号步骤，每步含「谁、在多长时间内、做什么」
- 高风险项要写明暂停或终止活动的授权人角色
- 联络表里的电话一律 `待确认`，只写角色与职责
- 必须写明「恢复活动」需要谁确认，不能只写处置

## 事实边界

- 不得编造应急电话、备用场地、医疗资源数量
- 不得编造不存在的应急队伍与联系人
- 未确认的联络方式一律 `待确认`

## 验收清单

- [ ] 输出是合法 JSON，章节与注入模板逐字一致
- [ ] 风险清单与台账逐项对应
- [ ] 响应流程为分步动作，含责任人与时限
- [ ] 未编造电话与外部资源

## 交付格式

- **主交付**：Word 文档（`.docx`）。章节标题映射为标题样式，Markdown 表格映射为 Word 表格。
- **备选**：Excel（`.xlsx`）与 Markdown（`.md`）。
- **导出入口**：「过程材料」卡片上的 `Word` / `Excel` / `Markdown` 按钮（`Word` 为主按钮），或页头的「导出材料包（Word）」。程序内对应 `window.WB.exporters.materialToDocx(doc)` / `materialToXlsx(doc)`。
- **写作要求**：用标准 Markdown 组织正文——`#` / `##` 标题、空行分段、`-` 列表、管道表格；不要写 HTML，导出时只识别这些结构。
