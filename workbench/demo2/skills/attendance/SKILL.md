# 签到表

## 何时使用

活动当天需要记录到场情况时。

## 输入

项目信息表（人数、时段）+ 报名表设计 + 排班表 +〔可选〕参与者信息收集（工作台「参与者」页已收到的记录与签到明细）。

## 输出契约

章节由调用方注入，逐字对齐。全部用 Markdown 表格。

## 各章要求

| 章节 | 内容 |
|---|---|
| 一、签到说明与统计口径 | 签到方式（纸质 / 扫码 / 两者并行）、有效签到定义、统计时点、责任人角色 |
| 二、观众签到表 | 序号 / 姓名 / 身份 / 单位或班级 / 联系方式 / 签到时间 / 签名 |
| 三、工作人员签到表 | 序号 / 岗位 / 姓名 / 到场时间 / 离场时间 / 签名 |
| 四、签到统计汇总 | 应到 / 实到 / 到场率 / 迟到 / 早退，留空供当天填写 |

## 表格要求

- 观众表预留行数按预计人数给出（如 30 行），并在说明里写明「如不足可续页」
- 项目已收集到参与者记录时，观众签到表改为按真实记录逐行填（序号 / 姓名 / 身份或班级 / 联系方式 / 签到时间），不再预留空行；统计汇总用真实的应到人数与实际签到人数算出到场率
- 只有「签到时间」这类当天才会产生的值，才允许留空由现场人员补
- 表头必须包含单位/班级、联系方式，方便后续核对
- 需要分组的活动（如分赛道、分队伍）增加「组别 / 队伍」列
- 统计汇总表数值栏一律留空，由现场人员填写

## 事实边界

- 不得编造姓名、学号、联系方式
- 不得编造第三方扫码工具与系统名称；工作台「参与者」页生成的扫码填写 / 签到入口是真实的，可以引用并写明「由活动工作台生成」
- 已收集到记录时，姓名、班级、联系方式只能取自记录，不得自行补充
- 没有收集记录时，到场率与实到人数一律留空

## 验收清单

- [ ] 输出是合法 JSON，章节与注入模板逐字一致
- [ ] 观众表与工作人员表分开
- [ ] 含统计口径与汇总表
- [ ] 未编造姓名与联系方式
- [ ] 有真实收集记录时按记录填充并给出到场率；没有记录时数值留空

## 交付格式

- **主交付**：Excel 工作簿（`.xlsx`）。每个章节一张工作表，表格首行为表头并冻结；纯正文章节按行铺开。
- **备选**：Word（`.docx`）与 Markdown（`.md`），内容与工作簿一致。
- **导出入口**：「过程材料」卡片上的 `Excel` / `Word` / `Markdown` 按钮（`Excel` 为主按钮），或页头的「导出材料包（Word）」。程序内对应 `window.WB.exporters.materialToXlsx(doc)` / `materialToDocx(doc)`。
- **写作要求**：每章用 Markdown 管道表格（表头行 + `| --- |` 分隔行 + 数据行），一张表只表达一件事；单元格内不要换行或嵌套列表——导出时按行、按列读取。
