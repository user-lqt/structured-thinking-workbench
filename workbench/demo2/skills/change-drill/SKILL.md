# 突发变更演练处置

## 何时使用

用户选定了一类突发变更场景（场地不可用、恶劣天气、设备故障、嘉宾缺席、审批整改、舆情、超员等），需要把它落到本项目上，得到「谁在多久内做什么」的处置脚本时。

## 输入

- 场景：标题、风险类别、阶段、触发信号、影响、预置处置步骤
- 项目信息表（活动名称、地点、备用地点、人数、主办与协办、审批要求、约束）
- 资源台账（可用于处置的人员、场地、设备、车辆）
- 任务分解表中该阶段的任务与责任人角色
- 风险台账中同类别的已有条目

## 输出契约

只输出一个 JSON 对象：

```json
{
  "steps": [{ "text": "处置动作，含责任角色与时限" }],
  "decisions": "本次演练的关键决策，2 句以内",
  "rollback": "满足什么条件、由谁确认后才恢复常态流程",
  "followUp": ["演练后需要补进预案或清单的改进项，最多 3 条"],
  "risk": { "name": "", "trigger": "", "prevention": "", "response": "", "escalation": "", "owner": "" }
}
```

## 各字段要求

| 字段 | 必须包含 |
|---|---|
| steps | 4-8 步；按时间顺序；每步写明「谁 + 在多少分钟内 + 做什么」；第一步必须是止损动作 |
| decisions | 写清取舍依据，例如「等待 vs 换场地」的判据 |
| rollback | 恢复常态的量化条件 + 授权确认人 |
| followUp | 可落地的清单式改进项，不要写「加强管理」这类空话 |
| risk | 可直接写入风险台账的一条，类别与阶段继承场景 |

## 写作要求

- 步骤要能被执行：出现具体角色（现场总协调、安保负责人、医疗组…），不写「相关人员」
- 时限用分钟或相对时间表达，如「3 分钟内」「开场前 30 分钟」
- 预置步骤可以调整顺序或合并，但不得整体丢弃；确实不适用要说明替代动作
- 涉及人身安全时，第一步必须是「先止损、先疏散、先救治」，不得先走流程

## 事实边界

- 不得编造应急电话、医疗资源数量、备用场地名称、外部单位联系方式
- 未确认的地点与联系人一律写 `待确认`
- 不得编造本项目中不存在的人员角色与设备

## 验收清单

- [ ] 输出是合法 JSON，无 Markdown 代码围栏
- [ ] steps 4-8 步且每步含责任角色与时限
- [ ] rollback 含量化条件与确认人
- [ ] risk 字段可直接写入风险台账
- [ ] 未编造电话、外部资源与不存在的人员

## 交付格式

- 本技能不直接产出可下载交付物，结果回写到工作台的结构化数据里。
- 需要带走时，使用所在视图的导出按钮（Markdown / 表格导出）。
