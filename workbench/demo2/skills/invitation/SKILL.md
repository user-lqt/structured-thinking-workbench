# 邀请函 / 通知稿

## 何时使用

需要请嘉宾、通知师生、发正式函件时。包括「邀请函」「通知稿」「请柬」。

## 输入

项目信息表（名称、时间、地点、主办单位）+ 任务分解表（接待相关任务）。

## 输出契约

章节由调用方注入，逐字对齐。函件正文用可直接送出的正式措辞。

## 各章要求

| 章节 | 必须包含 |
|---|---|
| 一、正式邀请函 | 称谓、活动名称与意义、时间地点、邀请事由、礼节性表述、落款（主办单位 + 待确认日期） |
| 二、嘉宾接待与动线安排 | 到达时间 / 迎接位置 / 休息区 / 引导人角色 / 发言或颁奖环节 / 离场安排 |
| 三、校内通知稿 | 面向师生的简要通知，含时间地点、参与方式、注意事项 |
| 四、回执与跟进 | 回执截止时间 / 回执方式 / 未回执跟进节奏 / 责任人角色 |

## 写作要求

- 邀请函用正式书面语，不分点罗列，成段书写
- 时间、地点、主办单位逐字来自项目信息表
- 接待安排必须落实到「几点、在哪、谁去接」
- 回执跟进要写明未回复时的处理动作，不要只写「及时跟进」

## 事实边界

- 一律不写具体人名，用「贵单位」「受邀嘉宾」「× 老师」这类角色称谓；姓名未知写 `待确认`
- 不得编造嘉宾职务、单位、头衔、电话
- 不得使用未经确认的荣誉表述（如「国家级」）

## 验收清单

- [ ] 输出是合法 JSON，章节与注入模板逐字一致
- [ ] 邀请函为正式成段文体，含落款
- [ ] 接待安排含时间、位置与引导角色
- [ ] 未编造人名、职务与联系方式
