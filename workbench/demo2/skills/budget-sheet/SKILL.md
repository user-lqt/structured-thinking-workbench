# 预算表

## 何时使用

需要估算经费、申报经费、说明钱的去向时。包括「做个预算」「经费怎么分」「要花多少钱」。

## 输入

项目信息表（预算上限、人数、场地、活动内容）+ 任务分解表（物料、宣传、场地相关任务）。

## 输出契约

章节由调用方注入，逐字对齐。每一节用 Markdown 表格承载。

## 分项原则

按用途分科目，覆盖这七类（没有的写 0 或说明不涉及）：

1. 场地与设备（租赁、搭建、用电）
2. 物料制作（横幅、展板、道具、证书）
3. 宣传品（海报、印刷、线上投放）
4. 人员与劳务（志愿者餐补、外聘讲师）
5. 奖品与纪念品
6. 运输与搬运
7. 应急预留

## 数值要求

- 金额写纯数字，不带单位与千分位
- 分项金额之和必须等于总额；总额不得超过项目信息表里的预算上限
- 单价的依据不能确定时写 `待确认`，**但金额栏仍要给出与总额自洽的数值或 `待确认`**
- 应急预留不低于总额的 5%
- 合计行必须存在于明细表末尾

## 各章要求

| 章节 | 内容 |
|---|---|
| 一、预算总览 | 科目 / 金额 / 占比 三列，含合计 |
| 二、分项预算明细 | 科目 / 明细项 / 单价 / 数量 / 金额 / 备注 |
| 三、经费来源与到位计划 | 来源 / 金额 / 到位时间 / 责任人角色 |
| 四、成本控制与审批流程 | 控制点 / 触发条件 / 审批人角色 / 记录方式 |

## 事实边界

- 不得编造供应商报价、赞助金额、报销额度
- 来源不明写 `待确认`
- 可以给出通用科目结构，但不得写成已确定的支出

## 验收清单

- [ ] 输出是合法 JSON，章节与注入模板逐字一致
- [ ] 分项金额之和等于总额，且不超预算上限
- [ ] 含应急预留，比例不低于 5%
- [ ] 未编造报价、赞助与报销数据

## 交付格式

- **主交付**：Excel 工作簿（`.xlsx`）。每个章节一张工作表，表格首行为表头并冻结；纯正文章节按行铺开。
- **备选**：Word（`.docx`）与 Markdown（`.md`），内容与工作簿一致。
- **导出入口**：「过程材料」卡片上的 `Excel` / `Word` / `Markdown` 按钮（`Excel` 为主按钮），或页头的「导出材料包（Word）」。程序内对应 `window.WB.exporters.materialToXlsx(doc)` / `materialToDocx(doc)`。
- **合计行**：明细表末尾保留**有且只有一行**「合计」（首格写字面「合计」）。工作台把它当成自动求和行：只重算原本就是数字的格，所以**单价、占比、备注这类不该求和的列请留空或写「—」**；已求和的格在界面里不可编辑、也没有删除按钮，新增行会插在它上方。生成时给一个自洽的数值即可，写错的合计会在预览与导出时按明细重算；**占比列**（表头带占比 / 比例 / 百分比 / 份额，或写成 `xx%` 的列）会按「本行金额 ÷ 合计金额」自动算出，合计行固定 100%——这些派生格在界面里都不可编辑。
- **发票栏**：「过程材料」里把发票文件拖到表格对应那一行即可上传，导出时自动在最右补一列「发票」并填上文件名（该行没有附件就不补列，正文 Markdown 不写入）。一行最多 6 张，单张超过 400 KB 只记文件名。
- **写作要求**：默认写成正文段落（空行分段、可用 `-` 列表），只有「本章本身就是一张清单 / 明细 / 登记表」时才用 Markdown 管道表格（表头行 + `| --- |` 分隔行 + 数据行），一张表只表达一件事，单元格内不要换行或嵌套列表。须知、说明、规则、口径、流程、职责这类内容不要塞进表格。导出时表格按行按列读取，正文段落整段铺进工作表。
