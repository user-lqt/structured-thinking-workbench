# 场地与资源方案

## 何时使用

需要确定场地怎么选、怎么布置、需要哪些设备，或用户提到「场地」「布置图」「设备清单」「备用场地」。

## 输入

项目信息表（人数、场地、备用地点、时段、内容）+ 任务分解表。

## 输出契约

章节由调用方注入，逐字对齐。正文用 Markdown，涉及清单用表格。

## 各章要求

| 章节 | 必须回答 |
|---|---|
| 一、场地需求与选型 | 容量、动线、舞台与后台需求；满足与不满足的取舍 |
| 二、场地布置方案 | 分区（入口 / 主会场 / 后台 / 医疗点 / 疏散通道）、座位与站位、指示标识 |
| 三、设备与物资需求 | 音响 / 投影 / 灯光 / 网络 / 用电负荷；数量与责任角色 |
| 四、用电、消防与安全要求 | 用电总负荷与分配、消防通道净宽、灭火器材位置、禁止事项 |
| 五、备用与切换方案 | 触发条件（下雨 / 场地被占用 / 设备故障）、切换动作、决策人与时限 |

## 写作要求

- 用条目与表格，不要大段描述
- 容量、面积、功率这类数字有依据才写，否则 `待确认`
- 备用方案必须写清「谁在什么时间点决定切换」，不能只写「视情况而定」
- 疏散通道、医疗点位置必须明确，不能省

## 事实边界

- 不得编造场地面积、承重、功率、租金
- 备用场地未知写 `待确认`
- 不得引用不存在的安全规范条款编号

## 验收清单

- [ ] 输出是合法 JSON，章节与注入模板逐字一致
- [ ] 含分区、动线、疏散与医疗点
- [ ] 备用方案有触发条件、动作、决策人与时限
- [ ] 未编造面积、功率与租金

## 交付格式

- **主交付**：Word 文档（`.docx`）。章节标题映射为标题样式，Markdown 表格映射为 Word 表格。
- **备选**：Excel（`.xlsx`）与 Markdown（`.md`）。
- **导出入口**：「过程材料」卡片上的 `Word` / `Excel` / `Markdown` 按钮（`Word` 为主按钮），或页头的「导出材料包（Word）」。程序内对应 `window.WB.exporters.materialToDocx(doc)` / `materialToXlsx(doc)`。
- **写作要求**：用标准 Markdown 组织正文——空行分段、`-` 列表、必要时用一张管道表格；只有「本章本身就是清单 / 明细」时才用表格，说明、规则、流程、职责一律写段落。不要写 HTML，导出时只识别这些结构。
