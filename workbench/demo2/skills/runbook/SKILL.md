# 现场执行手册

## 何时使用

活动临近或当天使用。包括「执行手册」「Rundown」「当天流程」「现场怎么走」。

## 输入

项目信息表（日期、时段）+ 任务分解表 + 排班表 + 风险台账 + 策划书中「活动内容与流程」章节。

## 输出契约

章节由调用方注入，逐字对齐。时间轴一律用 Markdown 表格。

## 各章要求

| 章节 | 必须包含 |
|---|---|
| 一、总体时间轴 | 从布置到撤场的关键时间点：到场 / 布置完成 / 观众入场 / 开始 / 各环节 / 结束 / 撤场完成 |
| 二、分环节 Rundown | 时间 / 环节 / 内容 / 负责人角色 / 配合岗位 / 所需物料 / 备注 |
| 三、岗位分工与通讯频道 | 岗位 / 位置 / 职责 / 对讲频道或联络方式 / 备份人 |
| 四、现场指挥与决策规则 | 谁有决策权、哪些情况必须上报、延误与取消的判断标准、计时与缓冲规则 |
| 五、收场与撤场流程 | 撤场顺序 / 物资回收清点 / 场地恢复标准 / 交接与离场确认 |

## 写作要求

- 时间精确到 5 分钟，写 `14:05–14:20` 这样的区间
- 每个环节都要有「负责人角色」与「配合岗位」，不能只有一个总负责
- 环节之间预留缓冲时间，并写明缓冲的用途
- 决策规则要给可判断的量化条件（如「延误超过 10 分钟」）
- 必须包含「如果环节提前结束怎么办」

## 事实边界

- 不得编造嘉宾姓名、节目名称、具体演出内容
- 时间未确认写 `待确认`，不要自行拼接
- 不得编造对讲机数量与频道号，未知写 `待确认`

## 验收清单

- [ ] 输出是合法 JSON，章节与注入模板逐字一致
- [ ] 时间轴覆盖布置到撤场
- [ ] 每环节含负责人与配合岗位
- [ ] 含延误判断标准与提前结束的应对

## 交付格式

- **主交付**：Word 文档（`.docx`）。章节标题映射为标题样式，Markdown 表格映射为 Word 表格。
- **备选**：Excel（`.xlsx`）与 Markdown（`.md`）。
- **导出入口**：「过程材料」卡片上的 `Word` / `Excel` / `Markdown` 按钮（`Word` 为主按钮），或页头的「导出材料包（Word）」。程序内对应 `window.WB.exporters.materialToDocx(doc)` / `materialToXlsx(doc)`。
- **写作要求**：用标准 Markdown 组织正文——`#` / `##` 标题、空行分段、`-` 列表、管道表格；不要写 HTML，导出时只识别这些结构。
