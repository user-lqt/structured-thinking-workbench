# 报名表 / 报名页

## 何时使用

活动需要收集报名时。包括「报名表」「报名链接要填什么」「怎么统计报名」，也包括校内小活动用手机扫码现场收集参与者信息（活动进行中随时补登、现场签到、边收边改）。

## 输入

项目信息表（人数、时间、场地、受众）+ 任务分解表（报名相关任务）+〔可选〕参与者信息收集（工作台「参与者」页定义的表单字段、已收到份数、签到人数、按学号去重的重复情况）。

## 输出契约

章节由调用方注入，逐字对齐。字段与统计口径用 Markdown 表格。

## 各章要求

| 章节 | 内容 |
|---|---|
| 一、报名须知 | 写成正文：谁能报 / 什么时候开始、什么时候截止 / 名额与超额怎么办 / 报名后想取消或改期怎么办 / 收集哪些信息、用来做什么、由谁保管 |
| 二、报名信息项 | 一张表，写报名者要填什么：信息项 / 是否必填 / 填来做什么。写的是「填写要求」，**不要出现数据类型、字符长度、正则表达式这类开发口径** |
| 三、报名统计口径 | 写成正文并附一张小表：报名数 / 有效报名数（按什么去重）/ 到场数分别怎么算、以哪个时点的导出为准、谁负责 |
| 四、截止与确认流程 | 写成编号步骤（`1. 2. 3.`）：截止前、截止当天、活动当天、收场后各做什么，每一步写清时点、动作、通知方式、责任人角色 |

## 信息项设计要求

- 必填项尽量少：姓名、联系方式、身份（学生 / 教师 / 校外）三类是底线，其余能选填就选填
- 团队类活动：队伍名称、人数、队长、成员名单
- 需要分组或分赛道的：要有对应的选择项，别让报名者在备注里自己写
- 涉及赛事的：要有「已阅读赛制」「需要特殊安排」两项
- 收集身份证号、健康信息这类敏感信息时，必须写明用途与保管责任角色
- 写的是「报名者看到并填写什么」，不是「系统里的字段配置」——不要出现数据类型、字符长度、正则表达式

## 现场收集（可选能力）

项目在「参与者」页开启了收集能力时，表单字段、填写页与二维码由工作台生成，属于本项目真实存在的东西，可以直接引用：

| 场景 | 写法 |
|---|---|
| 报名须知 | 写清收集哪些字段、用途、保管责任角色与截止时间；字段清单照抄「参与者」页的字段定义，不要自行增删 |
| 报名信息项 | 与「参与者」页的字段逐条对应，但只写报名者看得懂的三列（信息项 / 是否必填 / 填来做什么），**不要照抄「类型」与「校验规则」** |
| 报名统计口径 | 直接用真实数字：已收到份数、现场签到人数、按去重字段算出的重复人数、必填完整率；写明「数据来自活动工作台的参与者信息收集」 |
| 截止与确认流程 | 写清谁在什么时点导出名单、如何核对重复与缺席、如何通知 |

写作原则：

- 以「现场随时提交」为前提：统计口径要说明统计时点（如「以活动开始前 30 分钟的导出为准」），不要承诺实时锁定
- 不要写「扫码后自动分组」「自动发送短信」这类系统并不具备的能力
- 收集了手机号、身份证号等敏感字段时，必须写明用途与保管责任角色

## 事实边界

- 不得编造第三方报名平台名称与外部链接
- 项目已启用「参与者」页的收集能力时，填写页与二维码是真实存在的，可以写成「扫码填写（由活动工作台生成）」；没有启用时，文中不要出现具体的二维码与链接
- 名额、截止时间未知写 `待确认`
- 不得承诺「报满即止」这类未确认的规则

## 验收清单

- [ ] 输出是合法 JSON，章节与注入模板逐字一致
- [ ] 报名信息项与「参与者」页逐条一致，且只有面向填写人的口径（没有数据类型 / 长度 / 正则）
- [ ] 须知、统计口径、截止流程是正文段落，没有被硬塞进表格
- [ ] 统计口径覆盖有效报名与到场
- [ ] 未编造链接、平台与名额
- [ ] 引用的报名 / 签到数字来自「参与者」页的真实记录，没有真实数据时不写具体人数

## 交付格式

- **主交付**：Excel 工作簿（`.xlsx`）。每个章节一张工作表，表格首行为表头并冻结；纯正文章节按行铺开。
- **备选**：Word（`.docx`）与 Markdown（`.md`），内容与工作簿一致。
- **导出入口**：「过程材料」卡片上的 `Excel` / `Word` / `Markdown` 按钮（`Excel` 为主按钮），或页头的「导出材料包（Word）」。程序内对应 `window.WB.exporters.materialToXlsx(doc)` / `materialToDocx(doc)`。
- **写作要求**：默认写成正文段落（空行分段、可用 `-` 列表），只有「本章本身就是一张清单 / 明细 / 登记表」时才用 Markdown 管道表格（表头行 + `| --- |` 分隔行 + 数据行），一张表只表达一件事，单元格内不要换行或嵌套列表。须知、说明、规则、口径、流程、职责这类内容不要塞进表格。导出时表格按行按列读取，正文段落整段铺进工作表。
