# 风险评分校准

## 何时使用

风险清单已经生成，但分值分布不合格时：多数风险挤在 8–14 中档，高风险不足 2 项，或低风险不足 3 项。

## 输入

风险清单（每项的编号、名称、类别、阶段、挂靠任务）。

## 输出契约

```
{
  "scores": [
    { "index": 1, "probability": 1, "impact": 1 }
  ]
}
```

- **只输出分值**，不得增删风险、不得修改名称
- `index` 与输入编号一一对应，数量和顺序完全一致

## 评分锚点

**可能性 P**

| 值 | 含义 |
|---|---|
| 1 | 极低：同类活动几乎未出现过 |
| 2 | 较低：有先例但罕见 |
| 3 | 中等：同类活动偶有发生 |
| 4 | 较高：同类活动较为常见 |
| 5 | 很高：当前条件已具备苗头，几乎必然发生 |

**影响 I**

| 值 | 含义 |
|---|---|
| 1 | 极低：可忽略 |
| 2 | 较低：轻微影响，不影响主体流程 |
| 3 | 中等：影响部分环节或体验，当天可恢复 |
| 4 | 较高：导致环节取消、明显超支或参与人数显著下降 |
| 5 | 很高：人身安全事件、活动终止、重大舆情或合规事故 |

## 目标分布

`scores` 必须按分值从高到低排列，并满足：

| 位置 | 等级 | 分值 | 数量 |
|---|---|---|---|
| 最前面 | 高 | 15–25 | 2–4 项 |
| 中间 | 中 | 8–14 | 6–11 项 |
| 最后面 | 低 | 1–7 | 3–5 项 |

## 校准步骤

1. **忽略原有分值**，按锚点逐项独立打分
2. 按 `P × I` 从高到低排序（`index` 跟着风险走，不要重排 index）
3. 按下表核对各段数量，不符就重新打分
4. 只在确认合格后输出 JSON

> `index` 必须与输入编号一一对应，只是输出顺序改成按分值降序。

## 常见错误

- 把 3 当默认值：「较为常见」应该是 4
- 影响虚高：只有人身安全、活动终止、重大舆情或合规事故才配 5 分
- 影响偏低：直接影响参与人数或导致环节取消的，至少 4 分

## 验收清单

- [ ] `scores` 的数量与输入一致，`index` 连续
- [ ] 分值分布落在目标区间
- [ ] 没有增删或改名
