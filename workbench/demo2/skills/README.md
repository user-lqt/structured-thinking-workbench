# skills 目录说明

工作台里每一个「产出」都对应一个 skill。skill 不是一段写在代码里的提示词，而是一个**可独立维护的技能包**。

技能包分两层：本目录里的是**内置技能包（固定）**，跟着仓库走；使用者还能在工作台里导入**自定义技能包（可组装）**，存在浏览器本地。两层一起装配出界面上的「产出配置」——见本文件末尾「自定义技能包」。

## 目录规范

```
skills/
├─ registry.json          技能注册表：id、名称、类型、阶段、入口、状态、交付格式
├─ README.md              本文件
├─ _template/             新建 skill 时复制这一份
│  └─ SKILL.md
├─ manifest/              已就绪
│  └─ SKILL.md
├─ wbs/                   已就绪
│  └─ SKILL.md
└─ <skill-id>/            待接入（已在 registry.json 登记）
   ├─ SKILL.md            ← 必需
   ├─ references/         ← 可选，按需加载的细节规范
   ├─ assets/             ← 可选，模板与示例
   └─ scripts/            ← 可选，自检脚本
```

## 分层原则

| 层 | 放什么 | 何时加载 |
|---|---|---|
| `registry.json` | 一行摘要 | 启动时 |
| `SKILL.md` | 何时使用、输出契约、写作要求、事实边界、交付格式、验收清单 | 生成该产出时 |
| `references/*.md` | 具体格式规范、字段字典、写作细则 | SKILL.md 声明需要时 |
| `assets/*` | 模板、示例、参考成品 | 需要照抄结构时 |
| `scripts/*` | 校验脚本 | 生成后自检 |

**SKILL.md 只做路由，不要把所有内容塞进去。** 这样新增产出不会影响既有产出的上下文开销。

## 事实边界（所有 skill 共用，不得违反）

1. 只能使用用户已提供的事实。
2. 缺失的人名、单位、电话、金额、人数、依据一律写 `待确认`。
3. 不得编造任何可核查的具体信息。
4. 可以给结构性建议，但必须属于通用经验。

## SKILL.md 必备章节

- `## 何时使用`
- `## 输出契约`
- `## 事实边界`
- `## 交付格式`
- `## 验收清单`

## 新增一个 skill 的步骤

1. 复制 `_template/SKILL.md` 到 `skills/<skill-id>/SKILL.md`
2. 在 `registry.json` 里把该条目的 `status` 从 `planned` 改为 `ready`
3. 若需要，补充 `references/` 与 `assets/`
4. 工作台会自动识别并点亮该产出

## 自定义技能包（工作台内导入）

上面讲的是**改仓库**加技能。使用者自己也能在不动仓库的前提下加产出：「项目信息表 → 二、产出配置 → ＋ 自定义产出」，把一段技能包粘进去，识别通过就进产出配置。

- 格式就是这里的 `SKILL.md` 那一套 frontmatter（`name` / `title` / `kind` / `phase` / `output` / `description` / `sections`），正文写要求；行内 `#` 注释会被剥掉
- `sections` 一行一条（`- 一、xxx`），也接受 `|` 分隔或 `[a, b]` 流式写法
- `_template/SKILL.md` 的正文可以整段粘进去当正文；只贴 frontmatter 也能用，工作台会按章节补一段通用口径
- `kind: structure` 暂不开放（要工作台里有配套的专属视图）；`deliverable` 与 `kind` 必须自洽，不写就按 kind 推断
- 技能库存在浏览器本地（键 `demo2-custom-skills-v1`），**不写进本目录、不进 `registry.json`**；生成时由工作台把正文放进请求的 `rules` 交给服务端，用完即弃
- 弹窗里的「导出技能包」把整库导成一个 `.md`，别人粘进同一个弹窗就能装

实现都在 `core/skills.js`（格式识别 / 校验 / 本机技能库 / 注入产出配置与章节）；`tools/selftest.mjs` 里有一组断言盯着它：合法样例、`structure` 被拒、产出 key 与内置重名、章节不足、行内注释、模板自身可识别、加入 → 渲染 → 移除的往返。

## 参考样例（用户上传的样表）

「过程材料」卡片上的**上传参考**允许为某一份产出挂一份往届样表或学校样表（`.docx` / `.md` / `.txt`）。工作台在前端解析（Word 走 ZIP + `DecompressionStream`，不联网、不需要 API Key），并在生成时通过输入里的 `参考样例` 交给模型：

| 键 | 内容 | 用途 |
|---|---|---|
| `栏目` | 参考里的章节标题，含 Word 表格里的整行小标题 | 有参考时直接作为该产出的章节，逐字对齐 |
| `字段清单` | 表头与「活动时间」「负责人姓名」这类字段名 | 保证必填项不漏 |
| `表格表头` | 参考里每张表的首行 | 表格列结构一致 |
| `原文` | 参考正文的 Markdown 化文本（上限 10000 字） | 口径与写法的参照 |

四项约定（各 skill 的 `## 参考样例` 写本产出的细则，`_template/SKILL.md` 是通用版）：

1. 结构以参考为准：章节标题逐字一致、顺序一致，不自创、不合并。
2. 字段一个不漏：参考里的必填项都要写到，写不成表格就写「字段：值」。
3. 值不照抄：参考里属于别的事实的具体值换成当前项目的事实，缺失写 `待确认`。
4. 只增不改：当前项目有、参考没有的信息放进对应栏目，不新开栏目。

参考还有三个用处（都不需要写进 SKILL.md，工作台自己处理）：

- **版式跟着走**：导出 Word 时用参考的样式表、页面设置与页眉页脚——字体、字号、页边距、页眉页脚、表格线都沿用原表，正文换成生成的内容；卡片的参考条上显示「版式 ✓」。
- **按参考重排**：卡片上的「⇄ 按参考重排」把现有正文交给模型重写成与参考栏目、字段、表格列一致的成稿（契约要求照抄栏目顺序、逐条落字段、缺的写 `待确认`、不照抄参考里属于别的事实的值），正文会被替换，可「↺ 撤回重排」。
- **原表填值（离线保真）**：卡片上的「⇩ 参考表填值」把参考件本身当成一张待填的表——离线识别出栏目里的空位（标签格、正文段、表格数据格），你只填空位，「下载填好的 Word」导出的文档除这些空位外逐字节照搬参考（表格、栏目、条目数、缩进、页眉页脚全不变）。这条路径**不经过模型**；模型唯一可能介入的是「AI 补全空位」，契约是只回 { id, value }，不生成、不新增、不改动任何结构。SKILL.md 不需要为它写规则。

生成后工作台会用参考做**覆盖核对**：材料卡片与参考面板显示「栏目 x/y · 字段 a/b」，并把缺项列出来。核对只说明有没有写到，不判断内容对错。

章节优先级：**手选模板 > 参考样例 > `materials.js` 里的内置章节**。参考件随项目存档保存（`references`，按产出 key 存放），可在编辑器里换一份或移除。

## 交付格式与导出能力

`registry.json` 的每个技能都带一个 `deliverable` 字段，取值与 `deliverables` 图例一致：

| `deliverable` | 主交付 | 说明 |
|---|---|---|
| `word` | Word 文档 `.docx` | 章节标题 → 标题样式，Markdown 表格 → Word 表格 |
| `excel` | Excel 工作簿 `.xlsx` | 一章一张工作表，表格首行为表头并冻结首行 |
| `svg` | 矢量海报 `.svg` / `.png` | 文字由「海报设计器」叠加，不依赖图像模型 |
| `markdown` | Markdown / CSV | 工作台内的结构化数据表 |
| `none` | — | 不产出可下载交付物，结果回写工作台 |

三种格式随时都能导出，`deliverable` 只决定「过程材料」卡片上的主按钮：

- 单份材料：卡片右侧的 `Word` / `Excel` / `Markdown` 按钮
- 整包材料：页头的「导出材料包（Markdown）」与「导出材料包（Word）」
- 程序内：`window.WB.exporters.materialToDocx(doc)` / `materialToXlsx(doc)` / `materialsPackDocx()`

因此 `SKILL.md` 的正文要写成规范 Markdown：`#` / `##` 标题、空行分段、`-` 列表、管道表格。导出层只识别这些结构，写得越规整，Word / Excel 出来的排版越干净。

表格型产出还支持**发票栏**：在「过程材料」的「在线编辑」里把发票文件拖到表格对应那一行，导出 Word / Excel 时会自动在最右补一列「发票」并填上文件名；该行没有附件就不补空列，正文 Markdown 也不写入（附件另存在文档的 invoices 里，键为「章节:表块:行」）。
