# 访谈式补全

## 适用场景

项目已建立、信息表仍有空白字段时：由工作台逐题提问、用户作答，最后统一写回表单。

- `ask`：已有问题不够贴题，需要再补几条追问
- `draft`：用户对某一题说不清（例如写了「你帮我想」），要就这一题给几个可直接采用的版本
- `compose`：回答齐了，要整理成 `goal` / `content` / `constraint` 三个文本区的成稿

## 执行流程

1. 读 `活动类型 / 活动名称 / 已填信息`，先判断这是哪一类活动
2. `ask`：按「六类追问句式」挑最缺的几项，逐条追问，3–5 条
3. `draft`：就当前这一题给 2–3 个可直接采用的版本
4. `compose`：按「任务定制三条件」把回答整理成三个文本区

### 追问口径：每次追问 = 指认一个具体缺口 + 施加一条硬约束

- 六类句式：**依据 / 前提 / 反例 / 边界 / 替代 / 自评**，用 `style` 字段标出来
- 每条追问必须写 `why`：这一项不填会导致什么后果，20 字以内
- 优先「边界、替代、依据」；连追 2–3 类就够，不必六类都用；顺序建议：先依据 → 再边界 → 后替代
- 不写「你觉得怎么样」这类没有缺口的空问；不与已有问题重复

### 写作口径：任务定制三条件

- **定条数**：目标 1 条；内容 3–5 个环节；约束逐条列出
- **定顺序**：内容按时间先后；目标先写目标、再写衡量
- **不许推论**：只用用户给出的事实

### `ask` 细节

- `key` 只能取白名单内的字段名，不要发明新字段
- 问题要具体、可一句话回答，24 字以内
- 已填写的字段（日期、场地、预算等）不要重复问
- 贴着活动类型：科技文化节问展区与互动，运动会问赛制与天气备案，迎新问批次与站点，竞赛问赛制与评审标准

### `draft` 细节

- 每个版本必须自成一句、可直接粘进表单，40 字以内
- 版本之间要有真实差异：规模不同、风格不同、环节组合不同，不要同义改写
- 只给结构性建议（环节、形式、口径、衡量方式），不要编造人名、单位、电话、具体金额
- 涉及人数或金额时写成「≥ N」这类可核验的框架，或明确标注为参考区间

### `compose` 细节

- 只使用用户回答里出现过的事实，**不得新增**人数、单位、金额、场地、日期
- 每个字段都会给出「当前内容」：有内容时以它为基础**重写**，输出这一字段完整的替换版本，不要写成「旧 + 新」的拼接
- 输出会被整段替换进表单，所以原文里仍然成立的时间、场地、经费约束不能漏；原文里已经作废的说法可以删掉
- 回答不足以成句时原样保留用户的说法，不要自行补足
- 用户明确说「没有」或「暂无」的，写「暂无」；完全没问到的就留空，不要写「待确认」这类占位词
- 目标写成可核验的句子，带上用户给出的衡量指标
- 每项控制在 60 字以内，不要分点、不要 Markdown 标题

## 事实边界

- 用户没有提供的信息一律不得推断或补写
- 不得出现人名、电话、具体金额等用户未提供的内容
- 保持用户的口径与用词，只做润色与连句

## 输出格式

调用方会注入具体契约，以注入内容为准：

- `ask`：`{ "questions": [ { "key": "", "style": "依据|前提|反例|边界|替代|自评", "ask": "", "why": "", "hint": "" } ] }`
- `draft`：`{ "options": ["版本一", "版本二"] }`
- `compose`：`{ "basic": { "goal": "", "content": "", "constraint": "" }, "notes": [] }`

## 验收标准

- [ ] 输出是合法 JSON，没有 Markdown 代码围栏
- [ ] `ask` 的 `key` 全在白名单内、不与已有问题重复，且每条都写了 `why`（缺口）
- [ ] `ask` 的 `style` 取自六类句式，优先边界 / 替代 / 依据
- [ ] `draft` 的每一版都能直接采用，且版本之间有真实差异
- [ ] `compose` 符合任务定制三条件：定条数 / 定顺序 / 不许推论
- [ ] `compose` 按「当前内容」重写，输出的是完整替换版本而不是新旧拼接
- [ ] 没有编造用户未提供的人名、单位、金额、场地、日期；占位词一律不出现

## 交付格式

- 本技能不直接产出可下载交付物，结果回写到工作台的结构化数据里。
- 需要带走时，使用所在视图的导出按钮（Markdown / 表格导出）。
