# 方案比选决策矩阵

## 何时使用

活动目标已明确，需要在几种举办思路之间做选择时。包括「帮我比较几个方案」「怎么选更合理」「给几个方案并打分」。

## 输入

活动基本信息 + 已有方案与维度（可能为空）。

## 输出契约

```
{
  "options":  [{ "name": "方案名称", "summary": "一句话说明" }],
  "criteria": [{ "label": "评价维度", "weight": 3, "hint": "该维度看什么" }],
  "scores":   [{ "option": "方案名称", "criterion": "评价维度", "score": 3, "reason": "打分理由" }]
}
```

- `names` 必须与 `scores.option` 逐字一致，`criteria.label` 必须与 `scores.criterion` 逐字一致
- 每个方案 × 每个维度都要有一条 `scores`，不能缺格

## 方案要求

- 3 个方案，且**互斥**：选了 A 就不能同时用 B 的做法，不要给「A + B 结合」这类和稀泥选项
- 每个方案都要能用现有约束做得出来（场地、人数、预算、审批）
- 方案之间要有真正的取舍：成本低的牺牲体验，覆盖广的牺牲组织难度——不要给三个都差不多的方案
- 名称要具体，如「主会场集中式」，不要写「方案一」

## 维度与权重

- 5–6 个维度，权重 1–5
- 必须覆盖：目标契合、可行性、成本、风险、体验
- 权重反映本次活动最在意什么：预算紧的活动提高「成本可控」权重，安全敏感活动提高「风险可控」权重

## 评分要求

- 1–5 分，用足整个区间，**不要所有方案都给 3 分**
- 拉开差距的依据写进 `reason`，一句话，指向具体事实（场地容量、人力投入、审批周期）
- 同一维度内排序要有理由：谁更好、好多少，能说清楚才给分
- 若某方案在「风险可控」上明显更差，必须给 1–2 分，不要为了平衡而抬分

## 事实边界

- 只能使用输入中的场地、人数、预算等事实
- 涉及金额、单位、人名一律 `待确认`
- `reason` 可以引用通用经验，但不得编造具体数字

## 验收清单

- [ ] 输出是合法 JSON，顶层只有 `options` / `criteria` / `scores`
- [ ] 3 个方案互斥且可落地
- [ ] 维度 5–6 个，覆盖目标、可行性、成本、风险、体验
- [ ] 评分矩阵无空格，且分数有区分度
- [ ] 未编造具体金额、单位与人名

## 交付格式

- **主交付**：结构化表格导出（Markdown / CSV），由所在视图的导出按钮生成。
- **说明**：本技能维护的是工作台内的结构化数据，不产出可下载的文档；需要 Word / Excel 时，请到「过程材料」导出对应材料。
